# 세션별 코디네이터 보드

Paseo에서 여러 프로젝트를 운영할 때, 내가 결정할 일과 각 세션의 진행 상황을 한 화면에서 봅니다. **내 결정** 카드에서 작업 세션에 답하거나, 여러 작업의 순서를 조정해 달라고 코디네이터에 요청할 수 있습니다.

## 설치하고 첫 카드 보기

세션을 실행할 컴퓨터에 **Paseo 0.16.2 이상**이 필요합니다. 앱에서 **Settings → Plugins**를 열고 **Enable plugins**를 켜세요. **Plugin source**에 아래 설치 ID를 붙여 넣고 **Install plugin**을 누르세요. [공식 플러그인 페이지](https://paseo.sh/plugins/devbrother2024/coordinator-board)

```text
devbrother2024/coordinator-board
```

터미널에서 설치하려면 같은 컴퓨터에서 다음 명령을 실행하세요.

```sh
paseo plugin install devbrother2024/coordinator-board
paseo plugin ls coordinator-board
```

상태가 `running`이면 사이드바에서 **세션별 코디네이터 보드**를 열고 관리할 프로젝트를 선택하세요. 기존 세션은 **프로젝트별 진행**에 나타납니다. **추천 설정으로 시작**을 눌러 코디네이터를 만든 뒤 **설정 → 운영 세션 교체 → 다이제스트 요청**을 누르면 답변이 필요한 항목을 확인할 수 있습니다.

레지스트리로 설치한 보드의 새 버전을 확인하려면 `paseo plugin update coordinator-board --check`를 실행하세요. 업데이트하려면 `paseo plugin update coordinator-board`를 실행하고 제안된 변경을 확인합니다.

**Git·ZIP 설치**도 가능합니다. Git이 있는 호스트에서는 `paseo plugin install git:devbrother2024/paseo-coordinator-board --ref main`으로 기본 브랜치를 설치합니다. 이 문서의 버전을 설치하려면 `main` 자리에 `v0.5.24`를 넣으세요. 전체 커밋 SHA도 사용할 수 있습니다. ZIP은 압축을 푼 뒤 `paseo-plugin.json`이 있는 폴더에서 `paseo plugin install .`을 실행하고 그 폴더를 보관하세요. [Paseo 플러그인 안내](https://paseo.sh/docs/plugins)

**세션 진행 → 진행 중 모아보기**에서 선택한 프로젝트의 실행 중인 세션을 최근 활동순으로 확인하고 열 수 있습니다. 각 행에는 프로젝트와 실행 호스트가 표시됩니다. **프로젝트별**을 선택하면 칸반으로 돌아갑니다. 마지막으로 선택한 보기는 기기별로 저장됩니다.

**내 결정**에서는 기한이 지났거나 지금 처리해야 하는 카드가 맨 위에 옵니다. 그다음은 답변이나 권한 승인을 기다리는 작업이고, 나머지 카드는 오늘, 이번 주, 그 이후에 기한이 있는 작업, 기한 없는 작업 순으로 표시합니다. 같은 순위에서는 대기를 시작한 시각이 확인된 오래된 카드부터 표시합니다. 처음에는 다섯 장이 보입니다. 답변을 쓰거나 병합을 확인하는 동안에는 갱신이 와도 해당 카드의 자리를 유지합니다.

질문과 설명에서는 원래 줄바꿈과 마크다운을 볼 수 있습니다. 목록의 각 항목은 줄을 나누고, 코드나 경로는 고정폭 글꼴로 표시합니다. 날짜 범위나 근삿값의 물결표 하나는 그대로 표시합니다. 취소선을 넣으려면 `~~텍스트~~`처럼 글 양쪽에 물결표를 두 개씩 씁니다.

데스크톱과 웹에서는 요청, 답장, 추가 질문의 입력창에서 **⌘+Enter**(Mac) 또는 **Ctrl+Enter**(Windows·Linux)로 전송할 수 있습니다. **Enter**는 줄을 바꿉니다. 전송 버튼에 마우스를 올리거나 Tab 키로 버튼을 선택하면 이 기기의 단축키가 표시됩니다.

**내 결정**에서 답장을 보내거나 PR을 병합하면 방금 누른 자리에 카드 제목과 처리 결과가 남습니다. 답장을 보낸 뒤에는 접힌 카드의 **받은 세션 열기**를 눌러 답장이 도착한 대화를 바로 확인할 수 있습니다. 보낸 답장은 그 자리에 **답장 보냄**, 카드 제목, 보낸 시각(오늘이 아니면 날짜도)만 보이는 접힌 카드로 남고, **보낸 내용 보기**를 누르면 보낸 글 전체, 사진 장수, 받은 세션, 후속 응답의 첫 줄을 확인할 수 있습니다. 이 카드는 결정 수에 세지 않고 결정이 없을 때 **최근 결정 기록**이 저절로 펼쳐지는 것도 막지 않으며, 받은 세션의 후속 응답이 확인되거나 원장에서 카드가 내려가면 그다음 새로 고침에, 늦어도 보낸 지 24시간 뒤에 목록 아래의 **최근 결정 기록**으로 들어갑니다. 병합 같은 다른 결과 줄은 몇 초 뒤 저절로 접힙니다. 바로 치우려면 **숨기기**를 누르세요. 보내지 못한 답은 그 글이 다른 곳에 없으므로 **숨기기**를 누를 때까지 남습니다. 답장에는 보낸 문구와 시각이 표시됩니다. 받은 세션과 원래 질문을 올린 세션을 구분해 확인할 수 있습니다. 예전에 보드에만 저장한 답에서도 원래 세션을 찾을 수 있습니다. 보낸 답 전체는 **최근 결정 기록** 한곳에 모이며 위의 프로젝트 필터를 따릅니다. 아직 결과를 기다리는 답은 그 프로젝트 칸반의 **확인 대기** 칸에 **답 보냄 · 결과 기다림** 카드로도 보입니다. 카드에는 보낸 말의 앞부분, 보낸 시각과 지난 시간, 받은 세션 칩이 있고, 칩을 누르면 그 세션이 열립니다. 받은 세션의 후속 응답이 확인되거나 보낸 지 24시간이 지나면 이 카드는 칸반에서 내려가고 기록에만 남습니다. 보내지 못한 답도 24시간 동안 같은 칸에 **보내지 못함**으로 남습니다. 기기 로그인처럼 프로젝트에 속하지 않는 요청은 **공통**에 표시되며, 공통에 보일 카드가 없으면 이 구역은 숨겨집니다. 후속 응답은 기록 카드에 표시되며 세션 칩에서 대화 전문을 열 수 있습니다. 받은 세션을 지금 보드에서 찾지 못한 답(보관된 세션, 교체된 옛 코디네이터, 관리 범위 밖으로 옮겨진 세션 등)은 기록에 **받은 세션을 지금 보드에서 찾을 수 없어 결과를 확인할 수 없습니다**로 표시됩니다.

### 보드를 업데이트한 뒤에도 코디네이터 대화를 그대로 쓰기

보드를 업데이트해도 운영 중인 코디네이터를 교체하지 않습니다. 코디네이터 대화는 한 번 불러온 보드 도구의 정의를 기억합니다. Claude Code는 이 정의를 대화 기록에 저장해 이후 요청과 이어받기에도 그대로 보내므로, 세션을 다시 띄우거나 플러그인을 다시 불러오거나 Paseo를 다시 시작해도 바뀌지 않습니다. 그래서 보드는 코디네이터 도구의 이름과 입력 형식을 번호가 붙은 **계약**으로 고정하고, 새 기능은 고정된 도구 두 개로 냅니다.

- `read_board_guide`: 지금 설치된 보드가 받는 기능과 입력 형식, 그리고 대화가 도구를 받은 뒤 더해진 것(도구 정의 없이 낸 기능, 도구 정의에 없는 입력 항목)을 알려 줍니다.
- `board_action`: 이름으로 고른 기능을 지금 설치된 보드의 검사로 실행합니다. 대화가 가진 도구 정의에 없는 항목도 이 도구로 보냅니다. 결과와 권한 확인은 도구를 직접 부를 때와 같습니다.

기존 도구의 설명은 그대로 둡니다. 설명 문구만 바뀐 업데이트는 운영 중인 대화에 아무것도 알리지 않습니다. `board_action`으로만 닿는 기능이나 입력 항목이 새로 생기면 보드가 코디네이터의 다음 보드 도구 응답에 안내 도구를 읽으라는 알림을 한 번 붙입니다. 알림은 글로 답하는 응답에 한 번 붙습니다. JSON으로 답하는 응답은 바꾸지 않고, 알림은 다음 글 응답을 기다립니다. 코디네이터가 안내를 읽으면 그 대화에서 바로 새 기능을 씁니다.

계약이 생기기 전부터 이어진 대화와, 계약 번호가 호환되지 않게 바뀐 뒤의 대화에는 보드 맨 위에 **코디네이터 대화가 보드 업데이트 전의 도구 정의를 쓰고 있습니다**가 표시됩니다. 하던 일은 그대로 되며, 대화 맥락을 덜 잃는 순서로 풉니다.

1. 그대로 둡니다. 코디네이터가 다음에 보드 도구를 쓰면 안내 도구를 읽으라는 알림을 받고, 읽으면 안내가 사라집니다. 바로 하려면 **코디네이터 세션 열기**로 들어가 "보드 안내 도구를 읽어 줘"라고 직접 입력합니다.
2. 그래도 남아 있으면 코디네이터 세션에 `/compact`를 직접 입력합니다. 대화 요약은 남고, 압축이 끝난 뒤 보드를 새로 고치면 안내가 사라집니다. 보드는 코디네이터의 타임라인에서 압축이 끝난 것을 보고 판단합니다. 압축한 대화가 도구 정의를 새로 받는 것은 Claude Code 2.1.330에서 확인했고, 다른 버전에서는 다를 수 있습니다.
3. 마지막 수단으로 **새 세션으로 교체**를 누르거나 `/clear`를 직접 입력합니다. 교체하면 새 세션이 시작 지시에 따라 옛 코디네이터의 기록을 읽고 이어 갑니다(아래 **교체 뒤 인계**). `/clear`는 이전 대화 내용이 이어지지 않습니다.

보드는 `/clear`나 `/compact`를 대신 입력하지 않고, 세션을 다시 띄우지 않습니다. 보드를 업데이트하면 Paseo가 플러그인을 다시 시작하는 동안 코디네이터의 도구 목록에서 보드 도구가 잠깐 빠졌다가 돌아옵니다. 그 사이에 부른 도구의 오류는 Paseo가 내는 것이고, 잠시 뒤 다시 부르면 됩니다. 코디네이터가 아직 보드 도구를 부르지 않아 비교할 기록이 없을 때는 아무것도 표시하지 않습니다. 화면 안내와 알림은 Claude Code로 도는 코디네이터에만 냅니다. 다른 계정용 프로필처럼 실행기 ID가 달라도 Claude Code로 도는 세션이면 같은 대상입니다(Paseo가 세션에 적어 두는 실행기 구현 이름으로 판정합니다). 다른 실행기의 코디네이터도 두 도구를 받지만, 그 대화가 어떤 정의를 가졌는지 보드가 판단할 수 없어 아무것도 표시하지 않습니다.

이 동작은 Claude Code 2.1.330에서 확인한 것에 기대고 있습니다. 불러온 도구의 정의는 대화에 고정되고, 정의에 없는 항목을 넣은 호출은 클라이언트가 막지 않으며, 업데이트로 새로 생긴 도구는 기존 대화에 알려지고, 대화를 압축하면 정의를 다시 받습니다.

**계약 1로 넘어올 때.** 이전 버전에서 이어진 코디네이터 대화에는 위 안내가 한 번 표시됩니다. 1번대로 두면 됩니다. 새 도구 두 개가 그 대화에 알려지므로 교체, `/clear`, 압축 없이 풀립니다. 이후 업데이트는 같은 계약 안에서 교체가 필요 없습니다.

**플러그인을 고칠 때.** 코디네이터 도구의 이름과 입력 형식은 `shared/coordinator-contract.ts`의 계약 번호에 묶여 있고, `test/coordinator-contract.test.ts`가 스냅샷과 대조합니다. 새 선택 항목은 도구의 입력 형식을 그대로 두고 그 도구의 `accepts`에 더합니다. 그 항목은 `board_action`으로 받고 `read_board_guide`에 나옵니다.

### 교체 뒤 인계

새 코디네이터로 교체하면 새 세션에는 옛 대화 맥락이 없습니다. 교체를 확인하는 칸에서 이를 알리고, 보드는 새 세션을 만드는 요청에 시작 지시를 함께 담습니다. 시작 지시는 **[Coordinator Board · 코디네이터 시작]** 머리말로 보드가 쓴 글임을 밝히고, 옛 코디네이터 세션 ID와 그 기록을 `read_board_conversation`으로 읽어 진행 중이던 일과 약속을 정리한 뒤 이어 가라는 안내, 지금 열린 내 결정과 원장 카드 수를 담습니다. 새 코디네이터는 운영 폴더처럼 관리 프로젝트 밖에 있는 옛 코디네이터의 기록도 이 도구로 읽을 수 있습니다. 보드가 교체해 만든 세션이 지금 코디네이터일 때 바로 앞 코디네이터 하나만 읽을 수 있습니다. 보드는 옛 세션에도 새 세션에도 따로 메시지를 보내지 않습니다. 보드 업데이트 안내에서 누른 **새 세션으로 교체**도 같은 흐름입니다.

옛 코디네이터는 교체한 뒤에도 그대로 둡니다. **설정 → 운영 세션 교체**에 **옛 코디네이터 · 보관** 줄이 생기니, 새 코디네이터가 기록을 읽은 뒤 **보관**을 누르세요. 옛 세션이 아직 진행 중이거나 권한 요청을 기다리면 버튼이 꺼지고 이유가 표시됩니다. 이 줄은 보드가 만든 코디네이터에만 나옵니다. 직접 지정했던 세션은 Paseo에서 정리하세요.

호스트 관리자는 플러그인 데이터 폴더(`$PASEO_HOME/plugin-data/coordinator-board`)에 `coordinator-start.md`를 두어 새 코디네이터마다 덧붙일 시작 지시를 정할 수 있습니다. 보드는 새 코디네이터를 만들 때마다 이 파일을 읽어 시작 지시 끝에 붙입니다. 파일만 있고 옛 코디네이터가 없는 첫 생성에도 붙입니다. 파일이 없거나 비어 있으면 무시하고, 앞 4,000자만 쓰며, 줄바꿈과 탭을 뺀 제어 문자와 양방향 제어 문자는 지웁니다. 예시는 다음과 같습니다.

```markdown
시작하면 운영 폴더의 START.md 절차를 먼저 따르세요.
```

## 첫 화면과 관리 범위

1. Paseo 사이드바에서 **세션별 코디네이터 보드**를 엽니다. 제목 아래 호스트 이름을 확인하고 **다이제스트에서 관리할 프로젝트 선택**에서 원하는 프로젝트를 추가합니다. 보드는 열린 동안 30초마다 갱신됩니다.
2. 관리 대상을 바꾸려면 **설정 → 보드에서 관리할 프로젝트 선택**을 엽니다. 세션이 아직 없는 프로젝트도 선택할 수 있습니다. 보드를 연 호스트의 임시 폴더에는 **임시 폴더** 표시가 붙습니다. 카탈로그에 없어도 보이는 세션이 있는 프로젝트는 선택할 수 있습니다. 프로젝트와 세션이 모두 사라지면 보드 필터에서 빠지며, 이 메뉴의 **목록에서 빼기**로 관리 목록에서 제거할 수 있습니다.
3. 다른 프로젝트의 작업 세션 하나만 포함하려면 **설정 → 다른 프로젝트의 세션 하나 연결**을 엽니다. 이름이나 ID로 검색한 뒤 원래 프로젝트와 워크스페이스를 확인합니다. 이미 관리 중인 대상 프로젝트를 선택하고 **이 프로젝트에 연결**을 누릅니다.
4. 연결한 세션은 대상 다이제스트와 칸반에 한 번 표시됩니다. 대화, 작업 파일, 세션 ID는 원래 워크스페이스에 남습니다. **프로젝트 연결 해제**를 누르면 원래 프로젝트도 관리 중일 때는 그 프로젝트에 다시 표시됩니다. 원래 프로젝트가 관리 범위 밖이면 보드에서 사라집니다.

**설정 → 보드 언어**에서 **한국어** 또는 **English**를 선택할 수 있습니다. 언어는 이 기기에 저장되고, 세션에서 읽은 질문과 직접 쓴 답은 원문으로 표시됩니다. [English overview](OVERVIEW.md)

## 코디네이터에 첫 작업 맡기기

1. 다이제스트에 넣을 프로젝트를 고른 뒤 **추천 설정으로 시작**을 누릅니다. 기본 헌장을 가진 코디네이터 세션이 전용 워크스페이스에 생깁니다. 같은 요청을 다시 누르면 기존 세션을 재사용합니다. 이미 사용하던 세션은 **설정 → 기존 세션에서 코디네이터 지정**에서 연결합니다. 자동 생성할 때는 호스트에서 코디네이터 역할을 지원하는 실행기를 고릅니다. 사용할 실행기가 없으면 기존 MCP 지원 세션을 지정할 수 있습니다.
2. **코디네이터에게 맡길 일**에 “편집 프로젝트의 자막 검수 결과를 정리해 줘”처럼 입력하고 **코디네이터에 요청 보내기**를 누릅니다. 지정한 세션이 관리 중인 프로젝트와 워크스페이스, 기존 작업, 사용 가능한 모델을 확인한 뒤 작업자를 배정합니다. 작업 위치가 모호하면 코디네이터가 확인하도록 헌장에서 안내합니다. **코디네이터 세션 열기**에서 답을 읽습니다. **설정 → 운영 세션 교체 → 다이제스트 요청**에서 현재 내 결정을 정리해 달라고 요청할 수 있습니다.
3. 첫 작업은 추천값으로 맡길 수 있습니다. 코디네이터가 작업 난이도를 판단하고 현재 호스트에서 쓸 수 있는 모델을 고릅니다. 직접 정하고 싶을 때 보드 상단 **설정 → 모델 배정**을 엽니다. 표 한 장에 A(최상)부터 D(기본)까지와 코디네이터가 어떤 일에 어떤 모델을 쓰는지, 추천인지 직접 지정인지, 예비 후보가 몇 개인지 나옵니다. 바꿀 줄에서 **바꾸기**를 누르면 그 줄 아래에 후보가 1순위부터 펼쳐집니다. **+ 후보 추가**로 모델을 골라 **1순위로 추가**하거나 예비 후보로 넣고, 줄마다 순서를 올리거나 빼거나 추론 강도를 바꿉니다. 바꾼 내용은 누르는 즉시 저장되고, 몇 초 동안 **되돌리기**로 직전 상태로 돌아갈 수 있습니다. 예를 들어 C급은 Cursor의 Gemini를 먼저 쓰게 할 수 있습니다. **추천으로 되돌리기**를 누르면 그 등급은 다시 기본 규칙을 따릅니다. 필수 훅을 요구하는 일은 Claude Code·Codex에 맡깁니다. 실제 모델 사용료는 내 계정의 구독·과금 조건을 따릅니다.
4. M은 코디네이터 자체를 생성하거나 교체할 때 사용할 모델입니다. M 후보를 바꿔 저장해도 현재 세션은 계속 일합니다. 담당자를 바꾸려면 **설정 → 운영 세션 교체**에서 **새 코디네이터로 교체…**를 열고 **새 세션으로 교체**를 누릅니다. 다른 모델로 바꾸려면 같은 칸에서 **모델 고르기**를 누르고 모델 하나를 고른 뒤 **이 모델로 교체**를 누릅니다. 추천 모델이 맨 위에 나오고, 코디네이터로 쓸 수 없는 모델은 이유와 함께 흐리게 표시됩니다. 추론 강도는 권장값이 미리 선택되어 있고 바꿀 수 있습니다. 고른 모델은 다음 교체의 기본값(M 1순위)으로 저장됩니다. **다음 교체에도 이 모델을 기본으로 사용**을 끄면 이번 교체에만 씁니다. 직접 고른 모델은 사용량 기반 배정보다 우선합니다. 새 세션을 확인한 뒤 담당자를 전환하며, 카드의 질문과 판단·기존 작업자는 이어집니다.

입력창은 글 길이에 따라 저절로 늘어나고 줄어듭니다. 글이 화면 높이의 60%를 넘으면 더 늘지 않고 입력창 안에서 스크롤됩니다. 요청, 답장, 추가 질문, 세션 기록 입력창이 모두 같습니다.

보낸 요청은 입력창 아래 **보낸 요청**에 최근 20건까지 남습니다. 펼치면 보낸 문구 전문과 시각, 첨부 사진, 전달 상태(전송 미확인, 전송됨, 전달됨)를 보고 **받은 코디네이터 세션**으로 그 대화를 열 수 있습니다. 전달됨은 코디네이터 대화에서 그 메시지를 확인했다는 뜻입니다. 코디네이터를 교체하기 전에 보낸 요청은 **받은 이전 코디네이터 세션**으로 표시됩니다. 사진은 호스트가 보관하는 최근 사진 메시지 20건 안에 있을 때만 다시 볼 수 있습니다. 기록은 호스트의 플러그인 데이터에 저장되며, 기록을 저장하지 못해도 요청은 그대로 전달됩니다.

**사진 첨부** · 데스크톱·웹의 작업 요청란과 **내 결정** 답변란에 사진을 끌어 놓거나 붙여 넣으세요. 클립 아이콘 **첨부 파일 추가**로도 선택할 수 있습니다. 미리보기에서 확인한 뒤 보내세요. PNG, JPEG, WebP를 최대 4장까지 지원합니다(장당 5 MiB, 합계 12 MiB). 한도를 넘는 사진과 가로나 세로가 8000px를 넘는 사진은 보내기 전에 자동으로 줄여 보냅니다. 긴 변을 줄이고 다시 저장하며, 미리보기에 줄인 크기(예: 8.0 MiB → 2.4 MiB, 4032×3024 → 2560×1920)가 표시됩니다. 다시 저장한 사진에서는 촬영 위치 같은 사진 정보가 빠지고, 움직이는 사진은 첫 프레임만 보냅니다. 원본은 보내거나 보관하지 않습니다. 50 MiB나 5000만 화소를 넘는 사진은 줄이지 않고 더 작은 사진을 고르라고 알립니다. 사진만 보내도 됩니다. 모바일 네이티브 앱에서는 해당 세션의 대화 입력창에서 첨부할 수 있습니다. 사진을 읽지 못하거나 한도 안으로 줄이지 못하면 파일을 다시 선택하거나 실패한 첨부를 취소한 뒤 보낼 수 있습니다. 이 버전부터 사진을 첨부해 보낸 요청·답장·질문은 받은 세션에서 본문과 사진을 함께 볼 수 있습니다. 사진을 누르면 크게 볼 수 있습니다. 플러그인은 호스트에 최근 사진 메시지 20건의 원본을 보관합니다.

**결정에 답할 때** · 작업 세션이나 코디네이터가 받는 메시지에는 프로젝트, 원래 질문의 세션·카드·질문 ID와 판본, 질문 문구가 함께 들어갑니다. 예전 카드의 ‘Q3’에 답해도 어느 질문인지 수신자가 확인할 수 있습니다. 원래 세션 ID가 없는 예전 기록은 출처 원장과 카드 ID로 식별합니다. 수신자가 없는 카드의 답과 사진은 보드에 보관할 수 있습니다. 원장 카드에 답의 머리말(`answerLead`)이 있으면 질문에 답할 때 그 문장이 보내는 글의 첫 줄이 되어, 받는 쪽이 답이 무엇을 정하는지 알 수 있습니다. 첫 줄은 전송 버튼 위에 표시되며 **첫 줄 빼기**로 뺄 수 있습니다. 자유 답만 쓰면 쓴 그대로 보냅니다.

직접 확인한 항목은 입력란 아래 **추천 · 확인했어요** 칩을 눌러 답을 넣고 **보내기**로 알립니다(받는 곳은 버튼 옆에 보입니다). 카드는 그 답을 받은 코디네이터가 원장에서 내립니다. 필요 없어진 카드도 "필요 없어, 닫아"처럼 답해 받는 세션이 내리게 합니다. 보드에는 보내지 않고 카드를 닫는 버튼이 없습니다. 다이제스트를 요청하면 지정한 코디네이터는 단독 병합 안건의 GitHub 병합 상태와 작업 세션에서 확인한 완료 근거를 바탕으로 확인 기록을 정리할 수 있습니다. 후속 질문이나 사람의 선택이 남은 카드는 열려 있습니다.

**계정과 사용량** · 설정에서 현재 호스트가 알려 주는 기간별 잔여율과 초기화 시각을 확인합니다. 계정 카드마다 **자동 배정에 사용** 스위치가 있습니다. 끄면 보드가 그 계정에 작업을 배정하지 않습니다. 추천과 사용량 기준 선택에서 빠지고, 직접 지정한 목록에 남아 있으면 그 줄에 **자동 배정에서 꺼짐**으로 표시하고 건너뜁니다. 보드는 실행기 단위로 배정하므로 같은 실행기의 계정은 함께 켜지고 꺼집니다. 카드 위의 **사용량으로 순서 정하기**를 켜면 켜 둔 계정 가운데 같은 난이도와 실행 조건을 충족한 후보의, 최근에 측정한 같은 기간 잔여율을 비교합니다. 이렇게 고른 등급은 **모델 배정** 표에 **사용량 기준**으로 표시됩니다. 사용량 기준 등급을 직접 바꾸면 지금 쓰는 모델을 1순위로 둔 채 직접 지정으로 저장하고, 그 등급에는 사용량 선택이 적용되지 않는다고 알립니다. 직접 저장한 모델 순서가 우선이며, 보고되지 않은 계정의 잔여량은 미확인으로 표시합니다.

계정 카드의 막대는 **남은 비율**입니다. 총한도가 없는 크레딧은 잔액만 표시합니다. 초기화 시각 옆에는 지금부터 남은 시간(예: **5일 2시간 남음**, 하루 안이면 시간과 분, 1분 안이면 **곧 초기화**)을 붙이고, 설정 화면을 보는 동안 1분 단위로 갱신합니다. 이전 측정에는 조회 시각을 붙이며, 초기화 시각을 지난 값은 다음 조회까지 숨깁니다.

Paseo가 잔여 수치를 제공하지 않는 실행기는 호스트 관리자가 플러그인 데이터 폴더(`$PASEO_HOME/plugin-data/coordinator-board`, 기본 `~/.paseo/plugin-data/coordinator-board`)에 `account-usage.json`을 제공할 수 있습니다. 파일은 설정을 열거나 **실행기·모델 새로 고침**을 누를 때 읽습니다. `providerId`에는 실행기 ID, `fetchedAt`에는 원래 측정 시각을 씁니다. 다음은 형식 예시입니다.

```json
{"version":1,"reports":[{"providerId":"studio-runner","label":"Studio · 편집 계정","plan":null,"status":"available","fetchedAt":"2026-11-22T10:00:00Z","windows":[{"id":"weekly","label":"주간","remainingPct":72,"resetsAt":"2026-11-28T10:00:00Z","summary":true}],"balances":[],"resetPasses":[{"id":"weekly","label":"주간 초기화","left":2,"expiresAt":["2026-12-11T07:00:00Z","2026-12-20T07:00:00Z"],"note":"주간 한도를 처음으로 되돌림"}]}]}
```

보고마다 선택 칸 `resetPasses`로 구독이 주는 사용량 초기화권을 적을 수 있습니다. 항목마다 `id`와 `label`(64자 이내), 남은 장수 `left`(0 이상 정수), 만료 시각 목록 `expiresAt`(16개 이내), 짧은 설명 `note`(선택, 200자 이내, 비었거나 공백뿐이면 생략)를 씁니다. 형식이 틀린 항목만 버리고 나머지 보고는 그대로 씁니다. 계정 카드는 초기화권마다 남은 장수와 아직 지나지 않은 가장 가까운 만료일, 그때까지 남은 시간을 보이고, 0장이면 **없음**을 흐리게 보입니다. 남은 장수는 파일 값을 그대로 따르고, 지난 만료일은 표시에서만 뺍니다. Paseo가 사용량을 직접 주는 실행기도 같은 `providerId`의 보고가 있으면 Paseo 측정값은 그대로 두고 초기화권만 덧붙입니다. 이 경우 파일의 `windows`와 `balances`는 쓰지 않습니다. 실행기에 계정이 하나면 `label`과 무관하게 붙이고, 여럿이면 `label`이 정확히 같은 계정에만 붙입니다. 이렇게 붙인 초기화권에는 파일 보고의 `fetchedAt`을 따로 보이고, 계정 측정과 같은 기준으로 오래되면 **이전 보고**로 흐리게 보입니다.

호스트 추가 보고는 설정에 표시하는 용도입니다. 초기화권을 포함해 자동 배정에는 쓰지 않고, 자동 배정은 Paseo의 사용량 보고서를 사용합니다. 실행기가 같은 구독을 공유할 때도 계정별 비율을 합산하지 않습니다.

처음 만든 운영 워크스페이스는 이 호스트의 Paseo 사이드바에 자동으로 고정됩니다. **설정 → 사이드바 고정**에서 자동 고정을 끌 수 있습니다. 같은 워크스페이스에서 세션을 교체하면 사용자가 정한 고정 상태가 유지됩니다. 이미 쓰던 코디네이터를 고정하려면 **현재 운영 워크스페이스 고정**을 누르세요.

처음 만들거나 기존 운영 폴더에서 교체할 때 보드 언어에 맞춰 **코디네이터 운영 (삭제 금지)** 또는 **Coordinator operations (do not delete)** 이름을 정합니다. 이후 교체에서도 같은 폴더를 씁니다. 현재 쓰는 운영 프로젝트는 비어 보여도 지우지 마세요. 연결이 끊기면 보드 상단에서 새 코디네이터로 교체할 수 있습니다.

코디네이터에 닿을 수 없으면 보드 맨 위에 이유가 표시됩니다. 세션이 닫혔거나 오류 상태인 경우, 세션이나 워크스페이스가 보관된 경우, Paseo에서 운영 폴더의 프로젝트를 제거한 경우를 구분합니다. Paseo에서 프로젝트를 제거하면 그 워크스페이스가 보관되어 코디네이터가 요청과 답장을 받지 못합니다. **복구 방법 보기**는 다시 추가할 폴더를 알려 주고, **새 코디네이터로 교체**는 그 자리에서 교체 칸을 엽니다. 그동안 코디네이터에게 답할 카드에는 **코디네이터에 연결할 수 없음 · 위 안내 참고**가 표시되고 답장 보내기가 꺼집니다. 쓴 답은 카드에 남아 있으니 세션이 돌아온 뒤 보내세요. 원장을 맡은 세션이 현재 세션 목록에 없으면 **운영 코디네이터** 칩이 열기 전에 상태를 확인하고, 열 수 없을 때 빈 화면 대신 이유를 보여 줍니다. **설정**의 프로젝트 목록은 코디네이터 운영 폴더의 프로젝트를 알려 주며, 그 프로젝트를 제거하면 코디네이터가 함께 보관된다고 안내합니다.

처음 만들거나 교체할 코디네이터의 도구 권한은 버튼 위에서 확인합니다. 보드는 이 호스트가 제공하는 모드를 조회해 **Claude Code는 Auto mode**, **Codex는 Auto-review**를 우선 선택합니다. 우선 모드를 사용할 수 없으면 이 실행기가 제공하는 대체 권한 모드를 조회해 표시합니다. 이 두 실행기를 사용할 수 없으면 호스트에서 일반 작업 모드가 확인된 OpenCode(Build)나 Copilot(Agent)도 후보가 됩니다. 지원되는 모드를 확인할 수 없을 때는 실행기·모델을 새로 고치거나 Paseo MCP를 사용하는 기존 세션을 지정하세요. 다이제스트 요청은 지정된 코디네이터에 최신 질문과 결과를 정리하도록 요청합니다. 사실 질문 자동 답장이 켜져 있으면 코디네이터가 확인된 사실을 작업 세션에 전달할 수 있습니다. 자동 심사가 사람에게 돌려준 권한은 원래 세션에서 응답합니다. 새 작업 세션의 권한은 **설정 → Paseo 실행기 → 새 작업 세션 권한**에서 고릅니다. 배정할 때 해당 실행기가 선택한 모드를 지원하는지 확인합니다. 이미 사용하는 세션의 모드는 Paseo의 세션 권한 메뉴에서 바꿀 수 있습니다.

코디네이터는 관리 프로젝트의 워크스페이스에 새 작업 세션을 만듭니다. 배정 호스트를 추가하면 다른 기기의 워크스페이스도 사용할 수 있습니다. 외부 프로젝트에서 연결한 기존 세션은 지정된 그 세션만 관리 범위에 들어옵니다. 작업 요청·카드 답장·질문·다이제스트 전송과 작업자 실행에는 수신 세션의 모델 사용 조건이 적용됩니다.

## Paseo에 연결한 실행기 사용하기

**설정 → Paseo 실행기**를 열면 보드가 현재 호스트의 Paseo에 실행기와 모델을 묻습니다. 새로 연결한 실행기는 기본으로 배정 후보에 포함됩니다. 설정을 열어 둔 채 다른 도구를 연결했다면 **실행기·모델 새로 고침**을 누르세요. 각 항목에서 Paseo에 등록한 이름과 ID, 선택 가능한 모델 수, 배정할 수 있는 작업 등급을 확인할 수 있습니다. 모델이 없는 경우와 모델 목록을 읽지 못한 경우도 구분해 표시합니다.

예를 들어 코디네이터가 Codex여도 C급 작업자는 Cursor의 Gemini나 이 호스트에 등록된 다른 ACP 실행기로 지정할 수 있습니다. **모델 배정**에서 그 등급의 **바꾸기**와 **+ 후보 추가**를 누르면 모델이 실행기별로 묶여 나옵니다. 실행기·모델 이름과 ID로 검색할 수 있고, 그 등급에 쓸 수 없는 모델은 이유와 함께 흐리게 표시됩니다. 계정 하나의 남은 사용량을 알 수 있는 실행기는 묶음 제목 옆에 막대로 보여 줍니다. 같은 모델 ID를 제공하는 두 실행기는 서로 다른 후보입니다. 모델을 고르면 그 모델이 지원하는 추론 강도만 나오고 권장값이 미리 선택됩니다. Codex만 연결했다면 호스트의 Codex 모델에서 고릅니다. 연결된 Claude Code·Codex 모델이 없으면 일반 A·B 작업에도 다른 실행기의 모델을 추천합니다. 모델이 전혀 없으면 연결하거나 다시 포함할 실행기를 안내합니다. 저장한 우선순위가 있으면 사용 가능한 첫 후보를 씁니다. 1순위를 쓸 수 없으면 표의 그 줄에 이유와 실제로 쓰는 예비 후보가 나옵니다. 저장한 후보를 모두 사용할 수 없을 때는 후보를 바꾸거나 **추천으로 되돌리기**를 누르세요.

특정 도구를 쉬게 하려면 **계정과 사용량**에서 그 계정 카드의 **자동 배정에 사용**을 끄세요. 이후 배정은 포함된 후보 중에서만 고릅니다. 저장해 둔 후보의 순서는 유지되므로 다시 포함하면 같은 우선순위를 사용할 수 있습니다. 칸반 카드는 기존 세션이 실제로 사용하는 실행기와 모델을 보여 줍니다.

## 다른 기기의 세션 찾아보기

**설정 → Paseo 호스트**에는 앱에서 세션을 열 수 있는 기기와 보드에서 작업을 배정할 수 있는 기기가 표시됩니다. **숨기기**와 **표시하기**는 **기기별 세션 찾아보기**와 다른 호스트의 진행 중 목록에 적용됩니다. 오프라인 기기는 연결 상태를 표시합니다. 이름이 같은 기기는 이름 뒤의 식별자로 구분합니다.

## 여러 기기에 작업 배정하기

보드가 설치된 기기의 Paseo 데몬에 배정 호스트를 한 번 등록합니다. **설정 → Paseo 호스트 → 배정 호스트 등록 안내**에서 명령과 연결 안내를 확인하세요. 앱에만 등록했다면 그 기기 아래에 배정용 등록 안내가 표시됩니다. 등록 후 **배정 연결 새로 고침**을 누르면 연결 상태를 확인할 수 있습니다. 배정은 보드 데몬이 처리하므로 보드 화면을 닫아도 코디네이터가 배정할 수 있습니다. 대상 세션을 앱에서 직접 열려면 그 기기도 앱에 연결합니다. [Paseo 호스트 등록 안내](https://paseo.sh/docs/cli#connected-hosts)

1. 각 기기에 프로젝트를 준비하고 Paseo에서 작업할 워크스페이스를 엽니다. 보드는 원격 저장소 주소를 우선 비교하고, 주소를 확인할 수 없으면 고유한 프로젝트 이름으로 짝을 찾습니다. **배정 설정 → 프로젝트 짝**에서 직접 지정할 수 있습니다.
2. 각 기기의 **배정 설정**에서 운영체제를 확인합니다. 자동으로 확인하지 못한 경우 직접 지정할 수 있습니다. 작업 배정을 끄거나 동시 세션 상한을 설정할 수 있습니다.
3. 코디네이터에게 작업을 요청합니다. **배정 조건**에서 운영체제나 호스트를 직접 지정할 수 있습니다. 운영체제에 제한이 없으면 연결된 후보 중 진행 중인 세션이 가장 적은 기기를 고르고, 수가 같으면 현재 보드의 기기를 우선합니다. 지정한 조건에 맞는 기기나 워크스페이스가 없으면 보드에 배정 실패 이유가 표시됩니다.

배정으로 만들어진 원격 세션은 보드의 같은 관리 프로젝트에서 진행 상태와 배정 이유를 보여 줍니다. 현재 권한 요청이나 최근 대화에서 확인한 질문도 결정 카드와 다이제스트에 모입니다.

자체 배정기를 쓰는 코디네이터는 `assign_board_worker`의 `job.routeSource`를 `"coordinator"`로 지정해 선택한 실행기·모델·추론 강도를 전달할 수 있습니다. 보드는 대상 호스트의 카탈로그, 제외 설정, 필수 훅과 작업 권한 모드를 확인합니다. 보드의 등급별 배정표와 사용량 순서는 이 필드를 생략한 배정에만 적용합니다.

보드는 다중 호스트 배정 기록을 최대 256건, 30일 동안 보관합니다. 관리에서 뺀 프로젝트의 기록과, 지시가 전달된 뒤 세션이 보관되거나 삭제된 기록은 정리합니다. 새 배정에 자리가 필요하면 지시가 전달된 대기·종료 세션의 기록 중 보드 결정이나 답장 대기가 없는 것부터 오래된 순서로 정리합니다. 전달 미확인 기록도 생성 30일 뒤 자동으로 정리합니다.

보드는 기록을 정리한 뒤에도 세션 ID, 호스트 ID와 요청 키를 최대 1,024건, 30일 동안 따로 기억합니다. 같은 키로 재시도하면 이전 호스트를 사용하고, 그 호스트가 꺼져 있으면 실패를 알립니다. 남은 기록이 없으면 새 세션을 만들기 전에 연결된 다른 호스트에서 같은 세션 ID를 확인합니다.

### GitHub PR과 내 결정

사이드바와 **내 결정**은 관리 프로젝트의 세션 질문, 병합 검토 PR, 연결된 결정 원장을 함께 셉니다. 원장에서 같은 PR이나 같은 세션 질문을 확인하면 한 카드에 표시합니다. 관리 프로젝트에 GitHub 원격 저장소가 있으면 호스트의 GitHub CLI(`gh`)로 열린 PR을 조회합니다. 병합 조건을 충족한 PR은 **내 결정**에 뜹니다. **보드에서 병합**을 눌러 저장소, 대상 브랜치, 검토할 커밋과 사용할 병합 방식을 확인하세요. **병합 확정**을 누르면 호스트에 로그인한 GitHub 계정으로 요청을 보냅니다. 새 커밋이 올라왔거나 병합 조건이 바뀌면 다시 검토해야 합니다. 변경 내용을 읽으려면 카드 위의 **저장소 이름과 PR 번호**를 누르세요. GitHub에서 해당 PR이 열립니다. 초안이나 검사 중인 PR은 **프로젝트별 진행**에서 볼 수 있습니다. 여러 프로젝트가 같은 저장소를 쓰면 내 결정에서는 PR 한 건으로 셉니다. GitHub이 병합 가능 여부를 아직 계산하는 PR은 **GitHub이 병합 가능 여부를 계산 중**으로 보이고, 보드가 그 PR만 따로 다시 물어 곧 상태를 고칩니다. **상태 미확인**은 보드가 GitHub 상태를 읽지 못했거나 판정하지 못했을 때 보이고, 이유(조회 실패, 계산이 끝나지 않음, 결과 없는 검사, 알 수 없는 리뷰·병합 상태, 저장소 연결 없음 등)가 함께 표시됩니다. 원장 카드가 PR의 작업 세션(`agentId`, `sessionHost`)을 알려 주면 PR 줄에도 그 세션 칩이 뜹니다. 다른 기기의 세션은 그 기기에서 실제로 찾았을 때만 보입니다. 원장의 병합 카드는 GitHub에서 PR의 병합 준비가 확인될 때까지 **내 결정**에 올라오지 않고, **프로젝트별 진행**의 PR 줄에 상태와 이유로 남습니다. 확인되면 카드의 설명, 질문과 함께 내 결정에 올라옵니다. 보드에서 같은 저장소의 다른 PR을 병합해 기준 브랜치가 바뀌면, 열려 있던 병합 미리보기를 보드가 그 자리에서 다시 읽습니다. 병합은 새 미리보기에서 다시 눌러야 합니다. PR에 새 커밋이 올라와 멈춘 경우에는 같은 카드의 **최신 정보로 다시 확인**을 누릅니다. 원장 병합 카드의 PR이 GitHub에서 병합되거나 닫힌 것이 확인되면, 그 카드는 **내 결정**에서 바로 빠지고 **최근 결정 기록**에 **병합 완료 · 원장 정리 대기**(또는 **병합 없이 닫힘 · 원장 정리 대기**)로 남습니다. 원장 파일은 보드가 고치지 않고 코디네이터가 정리합니다. 그 줄의 시각은 보드에서 병합했으면 실제 병합 시각이고, 아니면 보드가 병합·닫힘을 확인한 시각(**보드 확인**)입니다. 병합 여부를 확인하지 못하면 카드는 그대로 둡니다.

원장에 저장소와 PR 번호가 있으면 승인·질문·확인 카드에서도 제목 아래 링크를 눌러 GitHub PR을 열 수 있습니다. 상태를 확인할 수 있으면 링크 옆에 표시합니다. 카드 제목과 본문의 `#42` 같은 번호는 원장에 지정한 저장소의 PR로 연결됩니다. 번호 바로 앞(조사는 떼고 봅니다)이나 바로 뒤 괄호에 보드가 아는 저장소·프로젝트 이름이 있으면(`alpha-web #12`, `alpha-web의 #12`, `#12 (alpha-web)`) 그 저장소의 PR로, 표에서는 머리가 "저장소"인 칸의 이름으로 연결됩니다. `owner/repo#12`는 보드가 아는 저장소일 때 연결됩니다. 보드가 아는 저장소는 프로젝트별 GitHub 저장소 설정, 원장, 열린 PR 목록, 병합 기록에서 모읍니다. 번호 옆 이름을 모르거나 여러 저장소에 맞으면 링크하지 않습니다. 옆에 이름이 없는 번호는 글 전체에 다른 저장소 이름이 하나도 없을 때만 원장 저장소로 연결합니다. 잘못된 PR로 가지 않도록 문장의 다른 곳에서 저장소를 짐작하지 않으므로, `Closes #12`처럼 이름 대신 일반 단어가 번호 앞에 오면 링크가 생기지 않을 수 있습니다.

코디네이터를 지정했다면 GitHub에서 병합할 수 있는 PR도 코디네이터가 확인해야 **내 결정**에 뜹니다. 코디네이터는 다이제스트에서 열린 PR마다 작업이 끝났는지, 리뷰 지적을 반영했는지, 검사가 그 커밋에서 통과했는지 보고 판단을 PR의 현재 커밋에 묶어 기록합니다. 준비됐다는 판단이나 코디네이터가 원장에 올린 병합 안건이 있어야 병합 카드가 뜹니다. 원장 안건이 있어도 이전 커밋에 대한 판단이 남아 있거나 현재 커밋에 준비되지 않았다는 판단이 있으면 뜨지 않습니다. 그 밖의 PR은 **프로젝트별 진행**에 **코디네이터 판단 대기**, **수정 필요: 이유**, **작업 중**, **막힘: 이유**로 남습니다. 판단한 뒤 새 커밋이 올라오면 **새 커밋, 다시 확인 필요**로 돌아가고, 병합 미리보기도 보드가 보여 준 커밋과 다르면 멈춥니다. PR과 연결된 작업 세션(같은 브랜치의 세션, 코디네이터가 지정한 세션, 원장 병합 안건의 세션)이 지금 그 PR 브랜치에서 진행 중이면 병합 카드를 **내 결정**에 올리지 않고 **진행 중** 칸에 **작업 세션 진행 중 · 끝나면 병합 카드로 올라옵니다**로 둡니다. 세션이 쉬면 다음 새로 고침에 병합 카드로 올라옵니다. 같은 세션이 다른 브랜치에서 다음 일을 하고 있으면 병합 카드는 그대로 뜨고 **작업 세션이 다른 일을 진행 중입니다** 한 줄만 붙습니다. 세션의 작업 브랜치를 알 수 없거나 그 세션이 있는 다른 호스트를 조회하지 못하면 병합 카드에 경고가 붙고, **보드에서 병합**을 누를 때 한 번 더 확인합니다. GitHub 상태만으로 병합 카드를 띄우려면 **설정 → 코디네이터가 확인한 PR만 병합 카드로**를 끄세요. 코디네이터를 지정하지 않은 동안에는 GitHub 상태만으로 띄우되, 현재 커밋에 준비되지 않았다는 판단이 남아 있으면 진행 칸에 둡니다.

GitHub가 보드에서 요청한 병합을 확인하면, 보드는 담당 코디네이터 세션에 PR 링크와 확인된 병합 커밋을 전달합니다. 코디네이터는 이 알림으로 후속 작업을 판단하므로 모델 사용량이 발생할 수 있습니다. 세션이 바쁘면 대기열에 두고, 카드와 **최근 결정 기록**에서 전달 상태를 확인할 수 있습니다. 다른 곳에서 이미 병합한 PR을 조회할 때는 알림을 보내지 않습니다.

병합 카드에는 **보드에서 병합** 아래에 입력창과 **수정 요청 보내기**가 있습니다. 병합 준비가 됐다는 판단이 났어도 고칠 점이나 물어볼 것이 있으면 여기에 쓰고 보냅니다. 사진도 붙일 수 있습니다. 받는 곳은 코디네이터가 그 PR의 담당으로 적은 작업 세션입니다. 그 세션이 없거나 보관됐거나, 종료·오류 상태이거나, 권한 요청을 기다리거나, 다른 기기에 있으면 코디네이터가 받습니다. 받는 곳은 버튼 옆에 보입니다. 받는 세션이 일하는 중일 때는 카드 답장과 같은 규칙을 따릅니다. Claude와 Codex 세션은 진행 중인 턴에 바로 받고, 그 밖의 실행기는 턴이 끝날 때까지 PR 줄에 **전송 대기**로 남았다가 세션이 쉬면 보냅니다. 기다리는 동안 **전송 대기 취소**를 누르면 요청이 지워지고 병합 카드가 돌아옵니다. 지정한 대기 시간이 지났거나 실행기가 턴 중 입력을 받지 못하면 **병렬 세션으로 맡기기**로 코디네이터에게 검토를 요청할 수 있습니다. 권한 요청을 기다리거나 오류 상태인 세션에는 보내지 않고 알려 줍니다. 받을 작업 세션도 코디네이터도 없으면 입력창 대신 그 이유가 보입니다.

보내면 그 병합 카드는 바로 내려가고 그 자리에 접힌 **수정 요청 보냄** 카드가 남습니다. PR은 프로젝트별 진행에 **수정 요청 보냄 · 새 커밋 대기**로 보이고, 원장의 병합 안건도 그 PR 줄과 함께 기다립니다. 새 커밋이 올라오면 앞선 판단은 풀리고, 코디네이터의 판단을 다시 거쳐 새 병합 카드가 뜹니다. 수정을 요청한 커밋은 새 커밋이 올라오거나 사람이 PR 줄의 **병합 카드 다시 열기**를 누를 때만 풀립니다. 코디네이터가 같은 커밋을 다시 준비됐다고 판단해도 병합 카드는 돌아오지 않습니다. 코드를 바꾸지 않고 끝난 경우에는 **병합 카드 다시 열기**로 되돌립니다. 이 버튼은 아무것도 보내지 않습니다. 수정 요청을 보낸 커밋은 보드에서 병합되지 않습니다. 다른 화면에 남아 있던 옛 병합 카드에서 **보드에서 병합**을 눌러도 보드가 거절하고 **병합 카드 다시 열기**를 안내합니다. 전송 결과를 확인하지 못한 요청도 도착했을 수 있어서 같은 방식으로 병합 카드를 내리고, PR 줄에 **수정 요청 전송 확인 중**으로 보입니다. 받은 세션에서 확인되면 보낸 것으로 바뀌고, 다시 보내려면 **병합 카드 다시 열기**를 누릅니다. GitHub에서 직접 병합하는 것은 막지 않습니다.

저장소를 자동으로 찾지 못했거나 다른 저장소를 보고 싶다면 **설정 → 프로젝트별 GitHub 저장소**에서 `owner/repository`를 입력하세요. **PR 조회 끄기**로 프로젝트별 조회를 끌 수 있습니다. 조회에 실패하면 보드를 연 호스트에서 `gh`의 설치와 저장소 접근 권한을 확인하세요.

## 내 환경에 맞게 고치기

ZIP에는 TypeScript 원본이 들어 있습니다. 기본 모델과 추론 강도는 보드에서 바꾸고, 기본 후보 선정 방식을 바꾸려면 `shared/dispatch.ts`를 확인하세요. 코디네이터에게 자동 적용되는 헌장은 `server/lifecycle.ts`, 배정 가능한 작업 공간을 조회하고 작업자에게 맡기는 도구는 `server/operations.ts`에 있습니다. 기존 세션에 자기 기준을 설명할 때는 [운영 예시](templates/coordinator-session.md)에서 공개·예산 변경처럼 직접 답할 일을 골라 적을 수 있습니다. 수정한 사본은 시험 호스트에서 다시 불러와 확인하세요.

## 보드 읽기

| 칸 | 들어오는 일 |
|---|---|
| 내 결정 | 실제 응답 대기, 세션이 대화에서 직접 청한 확인·선택, 카드에 기록한 질문이 있는 세션입니다. 카드에서 질문, 선택지와 수신자를 확인합니다. |
| 진행 중 | 작업 중인 세션 및 진행 중인 PR입니다. 코디네이터 판단을 기다리거나 작업 중으로 판단한 PR, 연결된 작업 세션이 아직 그 PR 브랜치에서 진행 중인 병합 가능 PR도 여기에 있습니다. 초안 PR에도 작업을 끝낸 세션이 연결될 수 있습니다. |
| 확인 대기 | 오류·새 결과를 살펴보거나 보고된 근거를 확인할 차례입니다. |
| 대기 중 | 대화가 쉬고 있습니다. 작업 결과는 아직 검증할 수 있습니다. |
| 완료 | 사람이 결과를 확인하고 카드에 완료 근거를 남겼습니다. 새 권한 요청이나 작업이 생기면 그 신호가 우선합니다. |
| 미확인 | 세션 초기화 중이거나 상태를 판정할 정보가 부족합니다. |

**확인 대기**의 세션 카드는 일을 마치고 쉬는 세션입니다(같은 칸에 고칠 것이 있는 PR과 결과를 기다리는 **답 보냄** 카드도 함께 놓입니다). 세션 카드는 시간이 지나도 저절로 **내 결정**으로 옮겨지지 않습니다. 결정이 필요하면 코디네이터가 판단해 결정 카드로 올립니다. 확인 대기와 대기 중 카드에는 쉰 시간("3시간째", "2일째")과 세션 마지막 글의 한 줄 요약이 보입니다. 요약은 "정지", "기다린다", "waiting"처럼 멈춘 이유를 말하는 문장을 먼저 고르고, 없으면 마지막 문단을 씁니다. 확인 대기 카드를 펼치면 마지막 글 전체를 볼 수 있습니다.

코디네이터가 지정돼 있고 확인 대기 세션이 정한 시간(기본 12시간) 넘게 쉬었는데, 그 세션을 가리키는 열린 원장 카드도, 코디네이터가 보낸 메시지나 현재 발췌에 대한 판단도 없으면 카드에 **코디네이터 미처리**가 붙습니다. 누르면 무엇을 해야 하는지 설명이 나옵니다. 시간은 **설정 → 코디네이터 미처리 표시**에서 6·12·24·48시간 중에 고릅니다. 코디네이터가 없으면 이 표시는 나오지 않습니다. 보드가 대화 발췌를 읽지 못한 세션(마지막 오류 세션, 대화를 읽지 못한 세션)에도 붙지 않습니다. 다이제스트를 요청하면 코디네이터는 이 표시가 붙은 세션을 먼저 읽고 분류합니다. 분류가 끝나면 표시가 사라집니다.

### 결정 카드에서 답하거나 조율 요청하기

원장 카드 머리 줄에는 프로젝트, 기다린 시간, 기한(있을 때)과 칩 하나만 보입니다. 칩은 답을 받을 세션을 엽니다. 코디네이터가 받는 카드는 **코디네이터 열기**, 작업 세션이 받는 카드는 **작업 세션 열기**입니다. 받을 세션이 닫혔거나 확인되지 않으면 카드에 이유가 보이고, 칩은 열 수 있는 쪽(대신 받을 코디네이터나 다른 호스트·프로젝트의 작업 세션)을 엽니다. 다른 쪽 세션(원래 작업 세션, 운영 코디네이터)은 **근거·이력 보기** 안에 있습니다. 프로젝트별 진행에서 카드를 접어 두면 두 칩이 모두 보입니다. 받는 곳은 **보내기** 옆에 적혀 있습니다.

원장 카드는 무엇을 묻는지, 추천은 무엇인지, 어떻게 답하는지만 펼칩니다. 요청 설명은 두 줄까지 보이고 **더 보기**로 펼칩니다. 추천은 한 줄로 보이며 전문은 **근거·이력 보기**에 있습니다. 원장의 진행 단계(`steps`)는 추천 바로 아래에 번호 목록으로 늘 보입니다. "아래 순서대로 확인" 같은 추천이 가리키는 순서를 카드에서 바로 볼 수 있습니다. 단계가 5개를 넘으면 처음 3개와 **단계 n개 모두 보기**가 보입니다. 근거, 위험, 이전 문답, 보낸 답 기록은 **근거·이력 보기** 안에 접혀 있습니다. 카드에는 입력창 하나와 **보내기** 하나가 있고, 답이든 질문이든 수정 요청이든 그 입력창에 씁니다.

질문이 둘 이상인 카드는 따로 버튼을 누르지 않아도 처음부터 답하지 않은 첫 질문을 보이고, 한 번에 한 질문만 보여 다음 카드가 화면에 들어옵니다. 질문 위에 **질문 3/10** 머리와 진행 점이 있고, 점을 누르면 그 질문으로 갑니다. 추천은 선택지 옆 **추천** 표시와 카드의 추천 줄로 보이고, 질문마다 직접 고릅니다. 하나만 고르는 질문은 선택지를 누르면 다음 질문으로 넘어가고, 여러 개를 고르는 질문과 직접 쓴 답은 **다음**으로 넘어갑니다. **이전**으로 돌아갈 수 있습니다. 직접 쓸 입력란은 **다르게(직접 적기)**를 눌렀을 때 열리고, 질문별 사진 첨부와 **이 질문 건너뛰기**는 질문 아래 **더 보기** 안에 있습니다. 마지막 질문 뒤에는 "Q1 A · 20장, 100 MiB" 같은 요약 목록이 보이고, 요약 줄을 누르면 그 질문으로 돌아가 고칩니다. 질문 아래에는 카드 입력창과 **보내기**가 늘 보입니다. 질문에 다 답하지 않았어도 이 입력창에 질문이나 수정 요청을 쓰면 그 글만 바로 보낼 수 있습니다. 입력창이 비어 있으면 지금처럼 모든 질문에 답하거나 건너뛰어야 보낼 수 있습니다. 보내는 글의 형식은 그대로이고, 쓰던 답은 질문을 오가거나 목록이 새로 고쳐져도 남습니다. 질문이 하나인 카드는 지금처럼 선택지와 입력란을 한 번에 보입니다. 답할 수 없는 카드는 질문이 여럿이어도 단계 없이 질문 전체를 한 번에 보입니다.

Claude·Codex 작업 세션과 코디네이터는 일하는 중에도 카드 답장을 받습니다. 진행 중인 턴은 계속됩니다. 열어 둔 세션 대화 카드는 보내기 직전에 같은 질문인지 다시 확인합니다. 대화가 바뀌었으면 최신 카드를 확인하세요.

진행 중에 답을 받을 수 없는 실행기는 답과 사진을 대기열에 보관합니다. 원장 카드에 `"deliverWhenIdle": true`를 넣거나 대화 질문에 `deliverWhenIdle: true`를 별도 줄로 쓰면 작업을 마친 뒤 답을 받습니다. 원장에서는 불리언 `true`만 유효합니다. 문자열 `"true"`는 무시하고 카드는 유지합니다. 대화에서 대소문자를 바꾸거나 줄 끝에 마침표를 붙여도 표식을 무시합니다. 이때 진행 중 입력을 받을 수 있는 세션에는 답을 바로 보냅니다. 권한 요청 중에는 전송하지 않습니다. 예약은 보드를 닫아도 유지되며, 전송 전에 질문과 수신자를 다시 확인합니다.

실행기가 진행 중 입력을 지원하지 않거나 대기가 10분에 이르면 **병렬 세션으로 맡기기**를 누를 수 있습니다. 기준 시간은 보드 설정에서 바꿉니다. 버튼을 누르면 원래 예약을 보류하고 코디네이터에게 작업이 겹치는지 확인하도록 요청합니다. 코디네이터가 별도 작업을 맡겼으면 **전송 대기 취소**, 원래 세션이 처리해야 하면 **원래 전송 재개**를 누르세요. 원래 세션이 끝났거나 보관되면 대기 취소만 가능합니다.

원장 카드의 답장 예시는 입력란에 흐린 예시로만 보이고, 입력란은 비어 있습니다. 카드에 추천이 있으면 입력란 아래 **추천 · …** 칩을 한 번 눌러 추천 답을 넣은 뒤 고쳐 보낼 수 있습니다. 넣을 글은 원장의 짧은 추천 답(`recommendedReply`), 답장 예시(`howToAnswer`, 추천대로 했을 때 보내는 문장), 추천 첫 줄 순서로 고르며, 짧은 것 가운데 앞의 것을 씁니다. 그래서 추천이 "연결 끊기" 같은 지시여도 답장 예시가 "연결 끊었어"면 칩에 그 문장이 들어갑니다. "A / B"처럼 고를 답을 나열하거나 `<시각>` 같은 빈칸이 있는 답장 예시는 건너뜁니다. 셋 다 없거나 길면 칩을 보이지 않고, 직접 확인 카드는 이때 **확인했어요**를 추천합니다. 선택지가 있는 카드에서는 **추천** 표시가 붙은 선택지를 직접 눌러 고릅니다. 작업 세션이 종료됐거나 다른 프로젝트·호스트에 있으면 카드에 이유가 표시되고, 확인된 운영 코디네이터에게 보내는 **운영 코디네이터에게 대신 보내기**를 고를 수 있습니다. 원장 소유자가 없는 카드에서는 이 버튼이 보드 코디네이터에게 보내는 **코디네이터에게 대신 보내기**로 보입니다. 이 버튼은 보내기 버튼 자리에 대신 나옵니다. 답을 받을 세션도 대신 받을 곳도 없는 카드는 이유만 보이고 답 입력란을 내지 않습니다. 원래 세션이 다시 답을 받을 수 있게 되면 보드는 대신 보내지 않습니다. 다른 프로젝트의 세션은 **설정 → 다른 프로젝트의 세션 하나 연결**에서 카드의 프로젝트로 연결하면 바로 보낼 수 있습니다.

경로의 대소문자만 다른 두 Paseo 프로젝트처럼 같은 폴더를 연 프로젝트는 같은 프로젝트로 봅니다. 그런 프로젝트에 있는 작업 세션에는 연결하지 않아도 바로 보낼 수 있고, 카드의 세션 칩도 그 세션을 엽니다. 같은 폴더인지는 보드가 디스크에 직접 확인합니다. 대소문자를 구분하는 디스크에서는 대소문자만 다른 경로를 다른 폴더로 보고, 이름만 같은 다른 폴더도 다른 프로젝트로 봅니다. 두 프로젝트 모두 보드에서 관리하고 있어야 합니다. 프로젝트 필터를 하나로 묶을 때와 같은 판단이며, 디스크가 늦게 답하거나 읽을 수 없으면 두 프로젝트를 따로 봅니다. 답을 보내는 순간에 디스크가 늦게 답하면 받는 세션을 찾지 못했다고 하지 않고 잠시 뒤 다시 보내 달라고 알립니다.

전송이 거절되면 원장에서 내려감, 카드 수정, 받는 세션 종료처럼 구체적인 이유가 표시되고 입력한 답은 그대로 남습니다. 근거·위험·긴급도·답장 예시·짧은 추천 답·문답 이력만 바뀐 카드에는 같은 답을 다시 보낼 수 있습니다. 제목·요청·추천, 질문과 선택지 설명, 받는 곳이 바뀌면 바뀐 내용을 확인한 뒤 보냅니다. 질문이 없던 카드에 질문이 생기면 그 전에 쓴 답은 안내와 함께 남고 질문의 답과 함께 보내지므로, 고치거나 **이 답 빼기**로 지웁니다. 질문이 바뀌어 붙일 곳이 없어진 사진은 빼야 보낼 수 있습니다. 전송 결과를 확인하지 못한 답은 카드가 바뀐 뒤 다시 눌러도 다시 보내지 않고 그 답을 받은 세션의 기록만 확인합니다. 카드가 다른 작업 세션으로 넘어가거나 원장 소유자가 바뀌어도 처음 받은 세션에서 확인합니다. 확인되기 전에는 그 카드에 새 답을 보내지 않으며, 10분이 지나거나 그 답을 받은 세션이 삭제·보관되면 바뀐 카드에는 새 답을 보낼 수 있습니다. 이때 앞서 보낸 답은 확인되지 않은 채로 남습니다. 그 답이 전달된 것으로 확인돼도 그 뒤 바뀐 카드는 열린 채로 남고, 카드에 그렇게 표시됩니다. 같은 이유로 두 번 거절되면 세션을 열어 직접 답하도록 안내합니다.

카드 위 **작업 세션** 칩을 누르면 원래 대화가 열립니다. PR 번호는 GitHub 변경 내용을 엽니다. PR과 일치하는 작업공간이 있으면 세션 이름·호스트·상태를 표시하는 칩이 함께 뜹니다. **작업 세션 미확인**은 현재 조회 범위에서 연결을 확인할 수 없다는 뜻입니다.

보드 제목 아래 한 줄에 **전체**, 현재 선택한 프로젝트, 결정할 일이 있는 프로젝트를 표시합니다. 선택하지 않은 프로젝트는 결정 건수순으로 남은 너비에 들어가는 만큼 표시합니다. 선택하지 않은 0건 프로젝트는 펼치면 보입니다. 선택한 칩이 많은 좁은 화면에서는 가로로 스크롤할 수 있습니다. 오른쪽의 **+N**으로 펼치고 같은 자리의 **접기**로 한 줄로 돌아갈 수 있습니다. 모든 필터가 한 줄에 들어가면 버튼이 숨겨집니다. 열림 상태는 이 기기에 저장됩니다. 같은 폴더를 가리키는 관리 프로젝트는 필터 하나로 묶입니다. 이름이 같은 별도 폴더는 경로의 끝부분으로 구분합니다. 각 필터의 숫자는 현재 결정 건수이며 여러 프로젝트가 공유하는 PR은 한 번만 셉니다. 보고 싶은 필터를 누르면 **내 결정**, **최근 결정 기록**, **프로젝트별 진행**에 함께 적용됩니다. 선택한 필터를 다시 누르면 선택이 해제되고 **전체**를 누르면 모든 프로젝트가 보입니다.

**내 결정** 제목 옆에서 최근 다이제스트 시각을 확인할 수 있습니다. 마지막 다이제스트가 세 시간 이상 지났고 그 뒤 새로 들어온 미분류 작업 세션 질문이 있으면 **다시 모으기**가 표시됩니다. 요청이 전달되면 다음 다이제스트가 완료될 때까지 버튼에 **요청함**이 표시됩니다.

병합과 후속 작업을 함께 묻는 카드에서는 PR 번호를 눌러 GitHub로 이동할 수 있습니다. 카드의 PR 줄은 GitHub에서 읽은 상태(예: **병합 완료**)를 바로 보입니다. 보드가 병합·닫힘을 따로 확인해 카드를 최근 결정 기록으로 옮기기까지는 다음 새로 고침까지 걸릴 수 있습니다. 아래에 남은 질문의 선택지를 고르면 해당 질문에 대한 답만 전송합니다.

**내 결정**에서 먼저 결정할 질문 한 줄과 추천 답장을 읽으세요. 각 결정은 카드 하나에 표시됩니다. 추천 답장은 입력란에 미리 채워지며 그대로 수정할 수 있습니다. 추천 답장은 입력란이 글 길이만큼 늘어나 그대로 보이므로 바로 보낼 수 있습니다. 답장이 너무 길어 입력란 안에서 스크롤될 때만 **답장 전문 확인**이 나타나고, 눌러 읽었다고 알려야 전송 버튼이 켜집니다. 입력란 아래 **보내기**를 누르면 그 내용이 버튼 옆에 적힌 받는 곳으로 전달됩니다. 선택지가 있으면 카드에서 바로 고르고, 추천 답장이 없으면 입력란에 직접 답을 써서 보낼 수 있습니다. 예전에 만든 카드에서 **코디네이터에 추천 요청**을 누르면 그 질문 하나의 근거를 다시 검토합니다. 조율은 **다른 방법**, 원문과 추천 이유, 세션 이름과 실행 호스트는 **근거·이력 보기**에서 확인할 수 있습니다. 카드 머리 줄에는 프로젝트와 기다린 시간, **작업 세션 열기** 칩만 보이고, 긴 설명은 두 줄까지 보인 뒤 **더 보기**로 펼칩니다. 이전 문답도 **근거·이력 보기** 안에 있습니다.

작업 세션이 “(b)로 진행할까요?”처럼 이름표만 묻고 멈추면 카드는 질문 앞 내용과 선택지 설명을 함께 보입니다. 질문 아래 **선택지**에는 그 메시지와 앞선 메시지에서 찾은 이름표마다의 설명이 늘 펼쳐져 있고, **앞 내용**에는 질문 바로 앞에 쓴 글이 처음 4줄까지 보이며 **더 보기**로 펼칩니다. 앞 내용이 표에서 끝나면 표 머리와 함께 첫 줄이 보이고, 제목에서 끝나면 그 아래 첫 줄까지 보입니다. 프로젝트별 진행의 카드도 같습니다. 세션 기록에서 어떤 이름표의 설명을 찾지 못하면 카드에 그 사실이 표시되고, **작업 세션에 선택지 설명 요청**을 누르면 모든 선택지와 장단점, 추천 이유를 한 메시지로 정리해 달라는 문장이 카드 입력란에 채워집니다. 원장 카드나 코디네이터 카드가 설명 없는 이름표를 가리키거나 “세션 화면 참고”처럼 설명을 세션으로 미루면 같은 안내와 **코디네이터에 카드 보완 요청**이 보입니다. 두 버튼 모두 입력란을 채우기만 하며, 문장을 확인한 뒤 직접 보내야 전송됩니다.

보드가 작업 세션의 마지막 글에서 찾은 질문 카드도 원장 카드와 같은 순서로 보입니다. 맨 위 머리 줄(프로젝트, 기다린 시간, **작업 세션 열기**), 확인을 요청하는 문장(두 줄까지), 그 뒤에 이어진 글, **앞 내용** 순서입니다. 따옴표("…", “…”, '…', 「…」, 『…』)나 인라인 코드(`…`) 안에 인용한 질문은 확인 요청으로 보지 않으므로, 설명 속 인용이나 예시 문구만 있는 글은 질문 카드가 되지 않습니다. 번호나 불릿으로 시작하는 줄이 요청이면 번호와 목록이 카드에서 끊기지 않고 함께 보입니다. 닫는 ```가 없이 ```로 시작하는 줄은 일반 글로 보여, 그 뒤의 글 전체가 코드 한 덩어리가 되지 않습니다. 물음표나 "골라 주세요" 없이 **결정할 것:**, "결정이 필요합니다", "답이 필요합니다" 같은 머리말을 쓰거나, 따옴표로 답 문구를 보이고 "…라고 하면 됩니다"로 답하는 방법을 안내하거나, "답을 받고 바꾸겠습니다"처럼 답을 기다린다고 쓴 글도 확인 요청으로 봅니다. 머리말 아래에 불릿으로 답 문구를 이어 쓰면 카드는 머리말 줄부터 보입니다. "결정할 것은 없습니다", "답이 필요하면 알려 주세요", "답을 받고 반영했습니다" 같은 글은 질문 카드가 되지 않습니다.

보드가 세션 대화에서 찾은 질문은, 처리됐다는 근거가 나올 때까지 카드로 남습니다. 보드는 찾은 질문을 이 호스트의 설정에 기록해 두므로, 질문이 최근 대화 밖으로 밀려나거나 세션이 다른 일을 하는 중이거나 끝나도 카드가 남습니다. 다음 가운데 하나가 있으면 카드가 닫힙니다.

- 보드에서 그 카드에 답을 보냈고 세션에 도착했습니다.
- 세션이 뒤 글에 처리했다고 한 줄로 씁니다: `결정 반영: <요약>`, `Decision applied: <summary>`, 또는 질문을 원장으로 옮긴 경우 `질문은 카드 <이름>로 옮김`, `question moved to card <이름>`. 코드 블록이나 인용 속의 줄은 세지 않습니다.
- 같은 질문이 원장 카드로 옮겨졌고 그 원장 카드가 처리되었습니다. 원장 카드가 열려 있는 동안은 원장 카드가 질문을 보여 주고, 처리 기록 없이 원장에서 빠지면 다시 대화 카드로 돌아옵니다.
- 카드의 **처리됨으로 닫기**를 누릅니다. 이 호스트의 보드에만 기록하고 세션에는 아무것도 보내지 않습니다.
- 사람이 세션에 직접 쓴 글이 카드의 선택지나 추천 답과 맞습니다(예: `Q1 A`, `(b)`, 선택지 내용, 추천 답). 문항이 여럿인 질문 블록은 모든 문항에 답해야 하고, 같은 답이 열린 질문 둘 이상에 맞으면 어느 것도 닫지 않습니다.

다음은 처리 근거가 아니어서 카드가 남습니다. 사람이 세션에 다른 이야기를 쓰면 카드에 "세션에 답했을 수 있음 · 확인"이 붙습니다. 다른 세션의 메시지, 보드 알림, 하트비트는 세지 않습니다. 세션이 질문 없는 글을 이어 쓰면 "이 뒤로 세션이 n번 더 말함 · 아직 답 없음"이 붙습니다. 질문 뒤로 15번 넘게 말했거나 12시간이 지나면 카드가 흐려지고 "오래된 질문"이 붙지만 내려가지는 않습니다. 코디네이터가 사람 결정이 필요 없다고 판단해도 열린 질문은 가려지지 않습니다. 세션이 일하는 중이면 세션은 진행 중으로 보이고 카드는 내 결정에 남습니다. 세션이 끝나거나 보관되거나 보드가 찾지 못하면 "세션 끝남 · 미처리"로 남고, 답 입력 대신 **처리됨으로 닫기**만 보입니다. 한 세션에 처리되지 않은 질문이 여럿이면 가장 최근 질문이 카드가 되고, 앞의 질문들은 "이 세션의 이전 미처리 질문" 목록으로 그 카드 안에 남습니다.

카드마다 입력창은 하나입니다. 답이든, 결정하기 전에 묻고 싶은 것이든, 고쳐 달라는 요청이든 같은 입력창에 쓰고 **보내기**를 누릅니다. 예를 들어 “네 곳 중 어디를 먼저 확인하면 되나요?”라고 써서 보내도 됩니다. 사진도 첨부할 수 있습니다. 보드는 글을 분류하지 않습니다. 받는 세션은 카드 정보와 함께 글을 받고, 카드 정보의 `mayBe` 값(`decision`, `question`, `change-request`)으로 셋 가운데 하나일 수 있음을 압니다.

질문을 보내면 카드는 접히고, 받는 세션이 다시 물으면 새 카드로 열립니다. 보낸 카드는 그 자리에 접힌 **보냄** 카드로 남습니다. 받는 세션이 결정으로 처리해 원장에서 카드를 내리면 닫히고, 다시 물어 카드를 새 내용으로 올리면 새 내용으로 다시 열립니다. 원장 카드의 접힌 카드는 받는 세션의 응답 첫 줄을 보여 주며, 원장에서 카드가 내려가거나 하루가 지날 때까지 남습니다. 세션 대화 카드는 세션이 다시 물으면 새 카드로 뜹니다. 전에 **질문하기**로 주고받은 문답은 **근거·이력 보기**의 **문답**에 그대로 있습니다. 승인 요청 카드(도구 실행 등)는 보드가 대신 답할 수 없어서 **질문하기**만 남아 있습니다.

카드 글을 받는 세션(작업 세션, 코디네이터)은 이렇게 다룹니다. 결정이면 처리하고 카드를 내립니다. 질문이나 수정 요청이면 답하거나 반영하고, 사람이 정할 일이 남았으면 카드를 새 내용으로 다시 올립니다(원장 카드라면 주고받은 문답을 `qa`에 적습니다). 내용이 같은 카드는 보드에 다시 뜨지 않습니다. 보드가 만든 코디네이터는 헌장에서 이 안내를 받습니다. 직접 지정한 세션이나 이미 떠 있던 코디네이터에는 이 문단을 알려 주세요.

예를 들어 작업자가 “이 세션의 원래 프로젝트가 어디인가요?”라고 묻는다면 보드가 확인할 수 있는 사실입니다. **다이제스트 요청**을 누르면 지정된 코디네이터가 해당 세션에 프로젝트 정보를 보내고, **프로젝트별 진행**에 처리 기록을 남깁니다. 자동 답장은 호스트마다 기본으로 켜져 있으며 **설정 → 사실 질문 자동 답장**에서 끌 수 있습니다. 답장을 받은 세션이 모델을 실행하면 해당 제공자의 사용량에 반영될 수 있습니다. “작업 폴더를 지울까요?”처럼 사람의 판단이나 권한이 필요한 질문은 **내 결정**에서 검토합니다.

| 하려는 일 | 카드에서 누를 항목 | 받는 곳 |
|---|---|---|
| 추천대로 답하거나 선택지 고르기 | 입력란의 문장을 확인한 뒤 **보내기** | 버튼 옆에 적힌 받는 곳 |
| 내용을 고쳐 답하거나 직접 쓰기 | 입력란에서 수정 → **보내기** | 버튼 옆에 적힌 받는 곳 |
| 결정 전에 한 가지 더 묻기, 고쳐 달라고 하기 | 같은 입력란에 쓰고 **보내기** | 버튼 옆에 적힌 받는 곳 |
| 병합하지 않고 수정 요청하기 | 병합 카드의 입력란에 쓰고 **수정 요청 보내기** | PR의 작업 세션, 없으면 코디네이터 |
| 다른 일과 우선순위·역할 조율하기 | **코디네이터에 조율 요청** → **코디네이터에 조율 요청 보내기** | 지정된 코디네이터 세션 |
| 세션이 낸 질문에 답하거나 계획 승인하기 | 카드에서 선택지를 고르거나 답을 쓰고 **답 제출**, 계획은 **계획 승인** 또는 **계획 거절** | 요청이 열린 원래 세션 |
| Paseo의 도구 권한·모드 변경 요청 처리하기 | **작업 세션 열기** → Paseo의 승인 화면에서 응답 | 요청이 열린 원래 세션 |

### 보드에서 질문과 계획 승인에 답하기

세션이 작업을 멈추고 답을 기다리는 요청은 **내 결정**에 **응답을 기다리는 요청** 카드로 올라옵니다. 이 가운데 질문과 계획 승인은 세션을 열지 않고 카드에서 바로 답할 수 있습니다.

- **질문** · 카드에 질문 원문과 선택지가 그대로 보입니다. 하나만 고르는 질문은 선택지 하나를, **여러 개 선택 가능** 질문은 여러 개를 고릅니다. 맞는 선택지가 없으면 **기타: 직접 입력** 칸에 답을 씁니다. 하나만 고르는 질문에서는 선택지와 직접 쓴 답 가운데 나중에 고른 쪽만 남습니다. 모든 질문에 답한 뒤 **답 제출**을 누르면 세션이 그 답을 받고 작업을 이어 갑니다. **답하지 않고 닫기**는 답 없이 질문을 닫습니다. Paseo 앱에서 질문을 닫을 때와 같습니다.
- **계획 승인** · 카드에 계획의 첫머리가 보이고 **계획 전문 보기**로 전체를 펼칩니다. 승인 버튼에는 승인하면 무엇이 바뀌는지 적혀 있습니다(Claude Code는 **편집 자동 허용으로 전환해 구현 시작**, Codex는 **계획 모드를 끄고 구현 시작**). 승인은 한 번 누르면 확인 문구가 뜨고, **승인 확정**을 한 번 더 눌러야 보내집니다. **계획 거절 · 구현하지 않음**은 구현하지 않고 세션을 멈춰 둡니다. 이전 권한 모드로 돌아가 구현하는 선택지처럼 권한 모드를 더 넓히는 선택지는 보드에 두지 않으니 **작업 세션 열기**로 들어가 고르세요.
- **도구 실행, 모드 변경, 그 밖의 요청** · 셸 권한 카드에는 작업 폴더, 명령 묶음, 파일 대상과 위험이 표시됩니다. 민감한 파일이나 작업 폴더 밖 경로를 읽는 요청은 따로 표시합니다. 파일 읽기에는 심볼릭 링크 대상이 아직 확인되지 않았음을 표시합니다. 다른 호스트의 작업 카드에는 실행기가 제공한 요청 제목이 표시됩니다. 알 수 없는 명령과 삭제 명령이 섞여 있으면 두 위험을 모두 표시합니다. **명령 전문 보기**로 원래 명령을 펼칠 수 있습니다. 파일 작업과 MCP 도구 요청에는 작업 종류와 대상이 표시됩니다. 승인과 거절은 **작업 세션 열기**로 들어가 Paseo의 승인 화면에서 선택합니다. 보드에서 답할 수 없는 질문과 계획도 작업 세션에서 처리합니다.

보드에서 답하는 질문은 Claude Code, Codex, OpenCode가 사용자에게 묻는 질문이고, 계획 승인은 Claude Code와 Codex의 계획입니다. 다른 실행기나 확장이 띄운 예·아니요 창은 질문처럼 보여도 도구 실행을 승인하는 창일 수 있어서 작업 세션에서 답합니다. 답을 가려야 하는 질문은 입력한 글자를 가리고, 보낸 뒤에도 그 값을 카드와 기록에 남기지 않습니다.

보드는 버튼을 누를 때에만 답을 보냅니다. 선택지를 대신 고르거나 추천을 채워 넣지 않고, 사람이 고른 선택지와 직접 쓴 글만 답에 담습니다. 보내기 직전에 그 요청이 아직 기다리는 중인지 다시 확인합니다. 다른 화면에서 이미 답했거나 세션이 요청을 거두었으면 보내지 않고 **이미 처리됨**으로 표시합니다. 버튼을 연달아 눌러도 답은 한 번만 갑니다.

보낸 뒤에는 카드 자리에 결과가 남습니다. 세션이 답을 받으면 **보냄**과 보낸 내용이 표시됩니다. 전송에 실패하면 카드에 그대로 남아 다시 시도할 수 있습니다. 보냈지만 세션이 받았는지 확인하지 못하면 같은 답을 다시 보내지 않고 **다시 확인**과 **작업 세션 열기**를 보여 줍니다. 보낸 응답의 기록은 보드 플러그인이 도는 호스트에 저장됩니다. 응답을 보낸 적이 없으면 빈 기록으로 시작합니다. 보드를 다시 열거나 같은 호스트에 연결된 다른 화면에서 열어도 기록에 있는 요청에는 다시 답하지 않습니다. 기록을 읽지 못하면 카드에서 답을 보내는 기능을 잠급니다. 요청 내용은 계속 볼 수 있고 작업 세션에서 답할 수 있습니다. 요청이 한 세션에 여러 개 쌓여 있으면 카드 하나에 차례로 보입니다. 다른 기기의 호스트를 보드로 열었을 때에도 답은 그 호스트의 세션으로 갑니다.

보내기 전에 **받는 곳**과 문장을 확인하세요. 현재 세션의 대화 근거와 카드 상태가 바뀌면 보드를 새로 고친 뒤 응답합니다. 직접 보낸 답장은 결과를 기다리는 **확인 대기**에 반영됩니다. 질문을 보낸 카드는 받는 세션이 새 내용으로 다시 올리면 다시 열립니다. 결과를 확인한 다음 **기록 추가** 또는 **기록 편집**에서 완료 근거를 남기세요.

## 대화에서 사람 차례를 찾는 방법

보드는 선택한 프로젝트 안에서 응답이 끝난 세션의 최근 타임라인을 읽습니다. 최대 48개 항목에서 사용자·에이전트의 최근 대화 4개만 발췌하며, 발화마다 마지막 2,000자까지 사용합니다. 기본 분류는 “확인해 주실 것”, “어느 쪽으로 할까요?” 같은 한국어·영어 표현을 살펴보고 질문과 선택지를 표시합니다. 변화가 없는 발췌는 짧게 재사용합니다. 닫힌 세션은 보드가 다시 띄우지 않습니다.

기존 세션을 쓸 때는 **설정 → 기존 세션에서 코디네이터 지정**으로 들어가 관리 중인 세션을 고릅니다. 다음 대화용 실행 때 Paseo MCP가 연결된 코디네이터에 `read_board_conversation`과 `classify_board_conversation`이 붙습니다. 첫 도구는 관리 세션 목록이나 해당 세션의 최근 발췌를 읽고(목록에는 쉬는 세션의 칸, 쉬기 시작한 시각, 쉰 시간, 코디네이터 미처리 여부가 함께 나옵니다), 둘째 도구는 현재 발췌 ID에 질문·검토·대기 판단을 기록합니다. 새 작업을 위임받으면 `plan_board_assignment`로 관리 프로젝트, 세션, 워크스페이스와 모델 후보를 확인하고 `assign_board_worker`로 작업자를 생성합니다. 보드 업데이트로 대화가 가진 도구 정의에 없는 기능이나 항목이 생기면 `read_board_guide`가 알려 주고 `board_action`으로 부릅니다. 이미 열려 있는 세션이라면 턴이 끝난 뒤 해당 세션만 다시 불러오세요. 시험 호스트에서는 `paseo agent reload <세션 ID>` 후 코디네이터 도구가 나타났습니다. 코디네이터에게 [첫 요청](templates/coordinator-session.md)을 보내면 관리 세션을 살피고, 발췌와 기존 지시를 대조해 질문·확인 대기·대기로 분류할 수 있습니다. 새 발화가 들어오면 이전 발췌에 대한 판단은 다시 적용되지 않습니다. 이미 보드에 적은 사람의 질문은 기록 편집에서 직접 정리할 수 있습니다. 보드를 여는 동작 자체가 코디네이터를 실행하지는 않습니다.

## 내 세션에서 질문을 올리기

현재 보드와 같은 기기의 세션에서 `report_to_board`를 사용할 수 있습니다. 다른 기기에 배정된 세션의 질문은 보드가 최근 대화에서 확인합니다.

보드 조회와 직접 기록은 설치 직후 사용할 수 있습니다. 세션의 자동 보고에는 Paseo MCP를 지원하는 실행기와 호스트의 도구 연결이 필요합니다. Paseo 0.16.2의 설정 이름은 `daemon.mcp.enabled`와 `daemon.mcp.injectIntoAgents`입니다. 뒤의 설정은 호스트의 에이전트에 제공하는 Paseo 도구 전반에 적용됩니다. 제공 범위를 확인하고 사용 여부를 선택하세요. [Paseo MCP 설정](https://paseo.sh/docs/mcp)

1. 보고받을 세션 카드의 **기록 추가** 또는 **기록 편집**에서 **보드 보고 켜기**를 누릅니다.
2. 그 세션이 다음에 대화용으로 열리면 지원하는 실행기에 `report_to_board` 도구가 제공됩니다. 이미 실행 중인 턴은 그대로 진행됩니다. 선택한 코디네이터 세션에는 [설계·운영 시작 문장](templates/coordinator-session.md)을 자기 기준에 맞춰 붙여 넣을 수 있습니다.
3. 그 세션이 질문을 올리면 **내 결정**, 확인할 결과를 올리면 카드에 **세션 보고**가 표시됩니다. 도구는 자기 카드에만 쓸 수 있습니다. 사용자가 남긴 기록은 사용자가 직접 편집하거나 해제합니다.

### 선택지를 묻는 질문 블록

세션이 글의 맨 끝에 `board-question` 코드 블록을 쓰면, 보드는 그 질문과 선택지를 원장 카드처럼 그립니다. 선택지를 누르면 카드 입력창에 `Q1 · 캐시를 어디에 둘까요?: A · 메모리` 같은 줄이 채워집니다. 추천 선택지에는 **추천** 표시가 붙고, **추천 답 넣기**는 `recommendedReply`를 입력창에 넣습니다. 고른 표시는 입력창의 글에서 읽으므로, 그 줄을 고치거나 지우면 표시도 따라 바뀝니다. 보내는 것은 **보내기**를 누를 때뿐입니다. 선택지의 `does`, `pros`, `cons`는 **근거·이력 보기**를 펼치면 보입니다.

````markdown
두 곳을 비교했습니다. 어디에 둘지 정해 주세요.

```board-question
{
  "questions": [
    {
      "id": "Q1",
      "text": "캐시를 어디에 둘까요?",
      "options": [
        { "key": "A", "text": "메모리", "does": "프로세스 안에 둡니다", "pros": "빠릅니다", "cons": "재시작하면 비워집니다", "recommended": true },
        { "key": "B", "text": "디스크", "does": "파일로 남깁니다" }
      ]
    }
  ],
  "recommend": "A. 지금 규모에서는 메모리로 충분합니다.",
  "recommendedReply": "Q1은 A로 진행해 주세요."
}
```
````

| 필드 | 뜻 | 한도 |
|---|---|---|
| `questions` | 질문 목록(필수) | 1개에서 8개 |
| `questions[].text` | 질문(필수) | 500자 |
| `questions[].id` | 답에 붙는 짧은 이름표 | 24자 |
| `questions[].multi` | `true`면 여러 개 선택 | |
| `questions[].options` | 선택지. 비우면 글로 답하는 질문 | 8개까지 |
| `options[].key`, `options[].text` | 선택지 이름표와 내용(필수) | 16자, 300자 |
| `options[].does`, `pros`, `cons` | 고르면 일어나는 일, 장점, 대가 | 각 400자 |
| `options[].recommended` | 추천 선택지 표시 | |
| `recommend` | 추천 한 줄 | 600자 |
| `recommendedReply` | 그대로 보낼 수 있는 추천 답 | 2,000자 |

- 블록은 글의 마지막이어야 하고, 블록 안은 12,000자까지입니다. 블록 뒤에 다른 글이 있으면 블록으로 읽지 않습니다. 본문 중간에 예시로 인용한 블록은 그대로 글로 남고, 다른 코드 블록 안에 든 블록이나 들여쓴 블록도 질문으로 읽지 않습니다.
- JSON이 아니거나, 한도를 넘거나, 필수 값이 비었거나, 한 질문 안에서 `key`가 겹치거나, 질문의 이름표(`id · text`)가 겹치면 블록 전체를 쓰지 않습니다. 그때는 지금처럼 글 카드로 보입니다.
- 모르는 필드는 무시합니다. 제어 문자는 지우고 보여 줍니다.
- 블록 앞 글에 질문 문장이 없어도 블록이 있으면 결정 카드가 됩니다. 제목은 첫 질문입니다.
- 블록을 쓰지 않은 질문은 지금처럼 글 카드로 보이고, 코디네이터가 선택지를 옮겨 원장 카드로 다시 올릴 수 있습니다.

## 로컬 데이터와 제거

보드는 선택한 호스트에서 Paseo SDK로 세션·워크스페이스 목록을 조회합니다. 보드 조회는 모델을 호출하지 않습니다. 보고를 켠 세션의 실행기가 모델을 사용할 때는 해당 제공자 설정이 적용됩니다. 선택한 프로젝트의 대화 발췌는 호스트 메모리에 잠시 유지됩니다. 지정한 코디네이터가 발췌 도구를 호출할 때는 해당 모델의 대화 맥락으로 전달됩니다. 관리 범위, 세션 연결, 코디네이터의 판단 요약, 중복 전송 확인용 영수증은 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/scope.json`에 저장됩니다. 병합 카드에서 보낸 수정 요청(쓴 글 포함, PR마다 최신 하나)도 같은 파일에 저장됩니다. 직접 적은 질문과 근거는 그 호스트의 Paseo 홈 아래 `plugin-data/coordinator-board/notes.json`에 저장합니다. 설치 디렉터리와 분리되어 업데이트 뒤에도 보존됩니다.

질문과 근거 원문은 로컬 JSON에 평문으로 보관됩니다. 설치한 호스트에서 `paseo plugin ls coordinator-board`로 상태를 확인합니다. 잠시 끄려면 `paseo plugin disable coordinator-board`, 다시 켜려면 `paseo plugin enable coordinator-board`를 실행합니다. 설치 등록을 지우려면 `paseo plugin remove coordinator-board`를 실행하고 `paseo plugin ls`에서 목록을 확인합니다. 다른 호스트를 대상으로 할 때는 각 명령 끝에 `--host 호스트주소:포트`를 붙이세요. 디렉터리 설치의 원본 폴더는 별도로 보관됩니다. 직접 남긴 기록까지 지우려면 해당 호스트에서 보관할 기록을 먼저 확인하세요. 이 패키지는 MIT 라이선스로 배포합니다. ## 프로젝트별 칸반과 결정 원장

칸반에는 작업이 있는 상태가 함께 표시됩니다. 데스크톱에서는 열을 나란히 보고, 휴대폰에서는 상태별로 아래로 읽을 수 있습니다. 각 세션에 실행 호스트가 표시됩니다. 설정에서 표시하도록 선택한 다른 호스트도 연결되어 있고 프로젝트 소속을 확인할 수 있으면 **다른 호스트에서 진행 중**에 나타납니다. 세션 열기는 해당 호스트의 대화로 이동합니다.

프로젝트 운영자는 플러그인 데이터 폴더의 `tracked-decisions.json`에 독립적인 결정을 제공할 수 있습니다. 같은 세션에서 여러 작업을 맡거나, 실기 확인과 병합을 따로 추적할 때 사용하세요. 다음은 항목 한 개 예시입니다. `projectId`에는 보드에서 관리하는 Paseo 프로젝트의 실제 ID를 사용합니다.

```json
{"version":1,"items":[{"source":"studio","projectId":"YOUR_PROJECT_ID","id":"playback","kind":"check","title":"모바일 재생 확인","where":"human","steps":["휴대폰에서 영상을 재생하고 첫 자막을 확인하세요."]}]}
```

결정에 마감이 있으면 `dueAt`에 날짜 또는 시간대가 포함된 시각을 적으세요. `since`는 결정을 기다리기 시작한 시각입니다. 배포처럼 다음 단계가 이 결정에서 실제로 멈췄다면 `blocksWork: true`를 지정하세요. 병합 준비가 끝난 PR에 후속 작업이 있다는 근거가 없으면 일반 검토 순서를 따릅니다.

기존 프로젝트별 JSON 원장을 운영하는 호스트는 같은 폴더에 `tracked-sources.json`을 둘 수 있습니다. `version`은 1이고 `sources` 각 항목에 `source`, `projectId`, `projectTitle`, `directory`를 지정합니다. `directory`는 `decisions.json`이 있는 디렉터리의 절대 경로입니다. `repository`에 GitHub 저장소를 지정하면 병합 항목을 같은 PR과 연결합니다. `coordinatorFile`에는 원장을 맡은 현재 세션의 `agentId`를 담은 JSON 파일의 절대 경로를 지정합니다. 보드는 답장을 보낼 때도 소유자를 다시 확인합니다. 운영 세션을 확인할 수 없는 카드는 이유를 보이고 답을 보내지 않습니다. **내 결정**에서 A/B 선택지와 추천 표시, 직접 답변란을 확인하세요. 선택한 답을 확인한 뒤 수신자가 표시된 전송 버튼을 누르세요. 근거와 이전 문답은 펼쳐서 볼 수 있습니다. PR 병합은 별도로 확정합니다.

원장 카드의 `agentId`는 작업 세션 ID입니다. 선택 항목인 `sessionHost`에는 호스트 `serverId` 또는 앱에 등록한 이름을 적을 수 있습니다. 이름은 대소문자를 구분하지 않습니다. 호스트를 비우면 현재 호스트에서 먼저 찾고, 이어서 설정에서 표시한 온라인 호스트에서 같은 세션 ID를 찾습니다. 작업 세션 칩은 해당 호스트의 대화를 엽니다.

프로젝트 원장의 `questions[].options[]`에는 선택지를 구별하는 `key`와 화면에 표시할 `text`가 필요합니다. `does`는 선택의 결과, `pros`와 `cons`는 장단점으로 각각 문자열이나 문자열 배열을 받습니다. `note`에는 짧은 설명을, `recommended`에는 추천 여부를 참·거짓으로 적을 수 있습니다. 질문이 없는 카드에는 추천 칩으로 입력란에 넣을 짧은 답을 `recommendedReply`(문자열)로 적을 수 있습니다. 없으면 짧은 `howToAnswer`, 그다음 추천 첫 줄을 씁니다. 이 칸만 바꾸면 카드가 새 판본이 되지 않아 이미 답한 카드가 다시 열리지 않습니다. `label`, `detail` 같은 추가 필드는 무시합니다. `label`만 있고 필수 `text`가 빠지면 보드에 `text`를 쓰라는 안내가 표시됩니다.

```json
{"key":"A","text":"첫 번째 영상 선택","does":["첫 번째 영상으로 출시"],"pros":["검수 완료"],"cons":["교체 일정 필요"],"note":"출시 전 재생 확인","recommended":true}
```

읽을 수 있는 원장의 정상 카드는 계속 표시됩니다. **내 결정** 건수 옆의 작은 경고 표시와 **자세히**에서 형식이 잘못된 카드의 출처와 필드 경로를 확인할 수 있습니다. 원장 파일을 열 수 없거나 JSON의 `items` 배열을 읽을 수 없으면 해당 원장 출처가 경고에 표시됩니다.

원장의 답장이나 질문 이력을 읽을 수 없으면 해당 원장의 카드는 읽기 전용으로 표시됩니다. 이력이 복구되면 답장 전송과 저장을 다시 사용할 수 있습니다.
