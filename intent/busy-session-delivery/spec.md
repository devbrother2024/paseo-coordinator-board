# 카드 답장의 전달 조건

승인: 2026-11-25 유지관리자(세션)
상태: 승인

[요청 배경](intent.md)

| 요구 | 계약과 검증 |
|---|---|
| R1 | Claude와 Codex가 진행 중인 턴에 카드 답장을 받는다. 권한 대기와 오류를 차단한다. 다른 보드 작업의 전송 조건은 기존대로 유지한다. 실행기와 상태 조합을 시험한다. |
| R2 | 원장에 지정한 `deliverWhenIdle: true`와 대화 질문에 별도 줄로 쓴 같은 표시는 쉬는 시점까지 기다린다. 사람이 열었던 질문의 개정, 프로젝트, 수신자를 클릭과 예약 실행 때 다시 확인한다. 새 발화, 중복 클릭, 재시작을 시험한다. |
| R3 | 지원하지 않는 실행기 또는 지정한 대기 시간(기본 10분)에 병렬 요청을 허용한다. 버튼을 누르면 원래 예약을 보류한 뒤 출처를 붙여 지정된 코디네이터에게 답과 카드 정보를 전달한다. 코디네이터가 중복 여부를 확인하면 사람이 예약을 취소하거나 원래 전송을 재개한다. 전송 결과가 불확실해도 같은 요청을 자동으로 보내지 않는다. |
| R4 | 양 언어에서 대기 시간과 전송 결과를 확인한다. 기존 예약과 영수증을 읽고 첨부 사진을 보존한다. |

대기 답의 변경은 메시지 ID에 고정한다. 코디네이터가 없거나 권한 요청 중이면 원래 예약을 유지한다. 대기열을 먼저 보류하므로 병렬 검토 중 원래 세션이 쉬더라도 두 세션에 같은 일을 맡기지 않는다.

원장의 대기 표식은 불리언 `true`만 적용한다. 값의 형식이 잘못되어도 카드를 유지한다. 대화의 표식은 대소문자를 구분하며 마침표가 붙은 줄은 무시한다.

병렬 요청은 사람이 쓴 답과 요청의 출처를 구분하고, 승인 판단 전에 원래 세션 기록을 확인하도록 안내한다. 재개 버튼은 코디네이터가 새 세션에 일을 맡겼을 때의 중복 처리 위험을 알린다. 종료·보관된 원래 세션에는 보류 상태와 취소 버튼만 표시하며, 재개 시점에도 원래 세션을 다시 확인한다. 호스트를 읽지 못하면 상태 미확인으로 표시하고 보류한다.

턴 종료와 권한 요청 완료 훅은 해당 호스트의 플러그인이 실행 중일 때 도착한다. 원격 세션의 턴 종료나 플러그인 중단 중에 끝난 턴을 놓칠 수 있으므로, 스냅샷 조회도 사람이 이미 예약한 답을 다시 확인한다. 보류 중인 답은 건너뛰며, 대기 답은 개정과 수신 상태를 다시 확인한 뒤 전송한다.
