# 작업 중인 세션에 카드 답장 전달

생성: 2026-11-25 유지관리자 요청
승인: 2026-11-25 유지관리자(세션)
상태: 승인

## 요청과 성공 기준

사람이 카드에서 답장을 보내면 Claude와 Codex의 실행 중인 턴은 `steer`로 그 답을 받는다. 사람의 답에 새 안내 문장을 붙이지 않는다. 실행기가 진행 중 입력을 지원하지 않거나 카드에 `deliverWhenIdle: true`가 있으면 답을 보관한다. 권한 요청 중이거나 오류 상태인 세션에는 보내지 않는다.

대기 카드에는 대기 시간을 표시한다. 진행 중 입력을 지원하지 않는 실행기이거나 설정한 시간(기본 10분)이 지나면 사람이 병렬 세션을 요청할 수 있다. 버튼을 누르면 보드가 출처를 붙여 코디네이터에게 작업이 겹치는지 확인하도록 요청한다. 이 요청의 전송 결과가 불확실하면 다시 보내지 않는다. 코디네이터 도구 계약은 그대로 사용한다.

## 세션 대화 카드의 수명

원장 카드는 질문과 개정 번호가 있어 나중에도 같은 질문인지 확인할 수 있다. 세션 대화 카드는 끝난 턴의 최근 대화에서 만든다. 현재는 세션이 다시 일하면 일반 대화 카드를 생성하지 않으며, 답을 누를 때 다시 읽은 대화가 달라지면 전송을 거절한다.

전송할 때 같은 개정의 질문인지 다시 확인한다. 대화가 바뀌면 최신 카드를 확인하도록 안내한다. 이전 질문을 따로 보관해 나중에 승인하는 방식은 채택하지 않는다. 기존 카드 머리에는 질문과 개정이 들어 있다. 턴을 유지하는 동작은 전송 옵션으로 지정하며, 보드의 새 안내를 답에 넣지 않는다.

## 열린 질문

질문을 연 뒤 다음 턴이 시작되면 이전 대화 카드에 답할 수 있어야 하는가? 이번 구현은 보내기 직전 대화 버전이 같을 때만 전송한다. 질문 뒤 세션이 다시 일하면 버전이 대개 바뀌므로 대화 카드에서 진행 중인 턴에 바로 전달할 기회는 드물다. 원장 카드는 원장 항목의 지문(fingerprint)이 같으면 새 턴에서도 답을 받을 수 있다.

## 검증

원장 카드와 세션 대화 카드에서 사람이 누른 답장, 권한 대기, 실행기별 전달, 질문 교체와 중복 클릭을 각각 검증한다. 대기 기준 시간 전후와 병렬 요청의 출처 및 실패 처리를 검증한다. 실제 카드 컴포넌트에 예시 데이터를 넣고 넓은 화면과 390px에서 한국어와 영어 상태를 확인한다.
