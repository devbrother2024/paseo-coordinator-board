# Intent: 사람이 켠 규칙이 있을 때만, 읽기 전용 셸 요청을 보드가 한 번 허용으로 답한다

생성: 2026-11-25 유지관리자 요청
승인: 2026-11-25 유지관리자(세션)
상태: 승인

## 문제

작업 세션이 셸 명령의 실행 허락을 물으면 사람이 그 세션의 승인 화면에서 눌러야 한다. 파일을 읽기만 하는 명령도 마찬가지라서, 여러 세션을 함께 돌리면 사람이 읽기 요청을 누르는 데 시간을 쓴다.

다른 에이전트(코디네이터 포함)가 대신 답하게 할 수는 없다. 에이전트가 다른 세션의 권한 요청을 승인하면 사람의 감독을 건너뛰는 길이 되고, 실행기의 자동 심사도 그런 응답을 막는다. 그래서 판단을 에이전트에게 맡기지 않고, 사람이 켠 고정 규칙으로만 답하는 길이 필요하다.

## 바뀐 뒤의 모습

- 설정에 **읽기 전용 명령만 자동 승인** 스위치가 있다. 기본은 꺼짐이다. 꺼져 있으면 보드는 지금과 똑같이 동작한다.
- 켜면 보드가 관리하는 작업 세션의 셸 요청 가운데 조건을 모두 채운 것만 보드가 **한 번 허용**으로 답한다. 하나라도 어긋나거나 확인할 수 없으면 지금처럼 카드로 사람에게 온다.
- 자동 승인한 요청은 그 세션 카드와 설정의 최근 목록에 남는다.

## 영향받는 사람과 화면

- 보드를 쓰는 사람: 설정 화면(스위치, 안내 문단, 최근 자동 승인 목록), 프로젝트별 진행의 세션 카드(자동 승인 줄).
- 작업 세션: 조건을 채운 읽기 요청이 사람을 기다리지 않고 진행된다.
- 코디네이터: 바뀌는 것이 없다. 코디네이터 도구에는 이 스위치를 읽거나 바꾸는 길이 없다.

## 제약

- 잘못 승인하는 것이 가장 나쁜 실패다. 판단할 수 없으면 승인하지 않는다.
- 에이전트의 판단을 끼우지 않는다. 규칙만 쓴다.
- 응답은 늘 한 번 허용이다. 지속 권한(항상 허용)과 바꾼 입력을 보내지 않는다.
- 세션에 메시지를 보내지 않는다. 이 일은 권한 응답이다.
- 새 요청이 생긴 훅에서만 답한다. 대기 요청을 주기적으로 훑어 답하지 않는다.
- 명령 분류는 권한 카드 요약의 분류기를 그대로 쓴다. 새 분류기를 만들지 않는다.

## 하지 않을 것

- git 명령의 자동 승인. 읽기 명령이어도 저장소 설정(외부 diff, textconv, fsmonitor, 페이저)이 코드를 실행할 수 있고, 그 설정은 작업 폴더 안의 파일이라 세션이 바꿀 수 있다.
- 폴더 전체의 내용 검색(`rg 패턴`, `grep -r`)의 자동 승인. 폴더 아래 모든 파일이 민감하지 않고 링크로 밖을 가리키지 않는다는 것을 보드가 보증할 수 없다.
- 작업 폴더 밖 읽기의 자동 승인.
- 질문, 계획 승인, 파일 편집, MCP 도구, 모드 변경 요청의 자동 응답.
- 코디네이터 세션 자신의 요청, 다른 호스트의 세션, 보드가 관리하지 않는 프로젝트의 세션.
- Windows 호스트. Windows 셸은 명령 줄을 다르게 읽는다(예: `sort /o`가 파일에 쓴다). 그 문법을 검사하는 분류기가 없으므로 규칙을 쓰지 않고 이유를 설정에 보인다.
- 자동 승인하지 않은 이유를 카드에 보이는 일. 카드는 지금의 요약을 그대로 보인다.
- 실행기의 권한 알림을 막는 일. 알림은 보드가 답하기 전에 이미 나간다.

## 버린 대안

- **코디네이터가 판단해 승인**: 에이전트가 사람의 감독을 대신하게 된다. 실행기의 자동 심사가 막고, 보드의 "사람이 누른 버튼으로만 답한다"는 원칙과도 어긋난다.
- **카드에 "한 번 허용" 버튼만 추가**: 누르는 자리만 옮길 뿐 누르는 횟수는 줄지 않는다. 별도 일로 남긴다.
- **분류기의 "읽기" 판정만으로 승인**: 분류기는 카드에 보일 표시용이고 파일시스템을 보지 않는다. 심볼릭 링크, 폴더 순회, 실행기가 알려 주지 않는 작업 폴더를 놓친다. 그래서 규칙은 자기 명령 목록을 따로 두고, 글자 판단과 호스트 확인을 모두 지나야 승인한다.
- **기본 켜짐**: 사람이 켜지 않은 자동 응답은 없어야 한다.
- **실행기가 주는 지속 권한 제안을 써서 "항상 허용"**: 한 번의 판단이 뒤의 다른 명령까지 풀어 준다.
- **주기적으로 대기 요청을 훑어 답하기**: 플러그인이 멈췄다 켜질 때 오래된 요청에 뒤늦게 답하게 되고, 사람이 보고 있는 요청과 경합한다.

## 성공 기준

- 스위치가 꺼져 있으면 권한 요청 훅이 세션을 읽지도, 응답을 보내지도, 기록을 만들지도 않는다.
- 켠 상태에서 조건을 모두 채운 요청에만 `{ behavior: "allow" }`가 한 번 나간다.
- 리디렉션, 치환, 민감한 이름, 작업 폴더 밖, 링크로 벗어나는 읽기, git, 알 수 없는 명령, 이전 분류기를 우회했던 옵션 입력이 모두 사람에게 간다.
- 응답 호출은 한 곳(`shared/permission-responder.ts`)이고, 서버에서 그 함수를 쓰는 곳은 이 규칙뿐이다.

## spec에서 정할 것

- 조건의 정확한 목록과 순서, 실행기별 요청 형식.
- 기록의 저장 위치와 형식, 화면에 보이는 범위.
- 사람의 응답 기록(`answered-requests`)과의 관계.
