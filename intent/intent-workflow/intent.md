# Intent: 설계 갈림길이 있는 변경은 구현 전에 intent·spec·plan을 남기고, 그 승인 경로가 정해져 있다

생성: 2026-11-25 유지관리자 요청
승인: 2026-11-25 유지관리자(세션)
상태: 구현됨 (PR #52)

## 문제

이 저장소의 변경은 대부분 에이전트 세션이 구현하고 PR 하나로 올라온다. 그 과정에서 생기는 판단(왜 이 설계인지, 무엇을 버렸는지, 무엇으로 검증하는지)은 PR 본문, 커밋 메시지, 저장소 밖의 대화에 흩어진다.

- 다음 작업자(사람이든 에이전트든)가 "왜 이렇게 하지 않았나"를 찾으려면 닫힌 PR과 히스토리를 뒤져야 한다.
- 데이터 파일 형식, 코디네이터 도구 입력 형식, 전송 경계처럼 되돌리기 어려운 변경도 구현과 설계 검토가 한 번에 섞인다.
- 외부 기여자에게는 큰 변경을 어떻게 제안하고 승인받는지 정한 길이 없다.

## 바뀐 뒤의 모습

- 큰 변경과 계약·경계를 바꾸는 변경은 `intent/<이름>/` 폴더에 `intent.md`, `spec.md`, `plan.md`를 남긴다.
- 유지관리자가 세션에서 지시한 일은 한 PR에 산출물과 코드를 함께 올리고(세션 경로), 외부 기여와 이슈는 산출물마다 PR을 연다(접수 경로).
- 규칙 전문은 `intent/README.md`, 에이전트용 요약은 루트 `AGENTS.md`, 외부 기여자 흐름은 `CONTRIBUTING.md`에 있다.

## 영향받는 사람과 화면

- 유지관리자와 에이전트 세션: 구현 전에 산출물을 쓰고 승인을 기록한다.
- 외부 기여자: 큰 변경을 이슈 → intent PR → spec PR → 기능 PR로 제안한다.
- 보드 사용자: 영향 없음. 설치 ZIP과 화면은 바뀌지 않는다.

## 제약

- 공개 저장소다. 산출물에 사람 이름, 원문 인용, 로컬 경로, 기기 이름, 실제 세션 ID를 넣지 않는다.
- 문서만 더한다. 코드와 버전은 바꾸지 않는다.
- 모든 PR의 base는 `next`다.

## 하지 않을 것

- 이슈를 감지해 다음 단계 PR을 자동으로 여는 자동화.
- 이 구조 이전의 변경에 대한 소급 작성.
- 진행 중인 PR과 이미 맡긴 일을 새 구조로 옮기기.

## 버린 대안

- **산출물을 비공개 운영 기록에만 둔다**: 원문과 개인 맥락을 그대로 쓸 수 있지만, 외부 기여자와 다음 작업자가 공개 저장소에서 설계를 읽을 수 없다. 공개 저장소에 intent·spec·plan을 두고, 원문과 개인 맥락만 저장소 밖에 둔다.
- **intent만 공개하고 spec·plan은 비공개로 둔다**: 동작 계약과 시험 기준이 공개 코드의 근거인데 그것만 감춰진다. 세 파일 모두 공개한다.
- **모든 일을 접수 경로로 처리한다**: 산출물마다 PR과 병합을 거치면 승인 기록은 분명하지만, 유지관리자가 세션에서 바로 정한 일도 PR 셋을 기다려야 한다. 세션에서 지시한 일은 한 PR로 묶고 승인은 세션 안의 발화로 남긴다.
- **모든 기능 PR에 intent를 만든다**: 문구, 작은 화면, 한 줄 버그에도 세 파일을 쓰면 문서가 일을 앞지른다. 설계 갈림길, 계약 변경, 경계 변경, 여러 PR로 쪼갤 일에만 만든다.

## 성공 기준

- 이 구조가 병합된 뒤 "언제 만드나"에 해당하는 새 변경이 `intent/<이름>/`의 세 파일과 함께 올라온다.
- 산출물에 공개 위생 검사로 걸리는 내용이 없다.
- 설치 ZIP에 `intent/`가 들어가지 않는다.
- 외부 기여자가 `CONTRIBUTING.md`만 읽고 접수 경로를 따를 수 있다.

## spec에서 정할 것

- "언제 만드나"를 이 플러그인의 계약·경계 목록으로 구체화.
- 승인 기록과 상태 표시의 정확한 형식.
- PR 템플릿을 브랜치별로 나눌지, 한 템플릿에 칸을 더할지.
