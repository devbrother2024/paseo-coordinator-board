# Spec: 사람이 답하기 전까지 세션 대화 카드가 사라지지 않게

Intent: [intent.md](intent.md)
승인: 2026-11-25 유지관리자(세션)
상태: 승인

## 1. 범위

- 판정: 대화 발췌와 질문 찾기(`server/conversation.ts`), 카드 만들기(`server/session-decisions.ts`), 답장 전 재검증(`server/decisions.ts`).
- 조립: 스냅샷(`index.server.ts`), 원격 배정 세션(`server/board-sessions.ts`).
- 계약: `SessionRow.keptQuestion`(`shared/contract.ts`), RPC `board.close-kept-question`(`shared/kept-question.ts`), 호스트 설정 `closedQuestions`(`server/preferences.ts`).
- 화면: 세션 대화 카드(`client/decision-actions.tsx`), 문구 판정(`client/kept-question.ts`).

이 폴더를 만든 이유: 사람에게 보이는 결정 목록에서 카드가 열리고 닫히는 조건이 바뀌고, RPC 하나와 호스트 설정 필드 하나가 생긴다.

## 2. 동작 계약

### 2.1 말

- **사람의 입력**: 타임라인의 사용자 메시지 전부. 사람이 쓴 글, 보드 답장(출처 없는 전송), 보드 추가 질문이 여기에 든다. 글이 비어 있어도(사진만) 사람의 입력이다.
- **사람의 입력이 아닌 것**: 출처가 붙은 에이전트 메시지와 하트비트(타임라인의 도구 호출 항목). 보드가 출처를 붙여 보내는 알림도 여기에 든다.
- **질문 글**: 지금의 판정(`turnQuestion`: 결정 요청 문장 또는 끝의 질문 블록)이 질문을 찾는 어시스턴트 글.
- **해결 줄**: 어시스턴트 글의 한 줄 전체, 또는 그 줄의 마지막 문장이 다음 가운데 하나. 앞뒤 공백, 끝의 마침표, 굵게 표시(`**`)는 무시한다. 영어는 대소문자를 가리지 않는다.
  - `질문 닫음`, `question resolved`, `question closed`
  - `질문은 카드 <이름>(으)로 옮김`(옮겼습니다, 옮겼어요 포함), `question moved to card <이름>`(`the`, `ledger` 허용)

### 2.2 발췌가 남기는 것

`excerpt`는 지금 내는 값(마지막 4턴 등)을 그대로 두고 `since`를 더한다.

- `since`: 마지막 사람의 입력 뒤의 어시스턴트 글(글이 빈 것은 뺀다), 오래된 것부터, 끝에서 31개까지. 사람의 입력이 발췌 안에 없으면 발췌의 처음부터 센다.
- 글마다 `key`(발췌 시대 `epoch`, 항목 번호 `seqEnd`, 원문의 해시 앞 24자)와, 해결 줄이 있으면 `closes: true`.
- 마지막 글이 사람의 입력이면 `since`는 없다.
- 코디네이터에게 내는 발췌(`read_board_conversation`)는 지금처럼 `turns`만 낸다.

### 2.3 남는 질문 찾기 (`openQuestion`)

1. 마지막 글이 어시스턴트 글이 아니면 없다.
2. 마지막 글이 질문 글이면 지금과 같다(남는 질문이 아니다).
3. 그 밖에는 `since`를 끝에서부터 거슬러 간다. 질문 글을 먼저 만나면 그 질문이 남는 질문이다. 해결 줄이 있는 글을 먼저 만나면 없다. 마지막 글의 해결 줄도 센다. 질문 글이면서 해결 줄이 있는 글은 질문 글로 본다.
4. `later` = 그 질문 뒤의 어시스턴트 글 수(1 이상).
5. 상한: `later`가 30을 넘거나, 질문 글의 시각이 24시간보다 오래되면 없다. 시각이 없으면 글 수만 본다.
6. 오래된 질문: `later`가 15를 넘거나 12시간보다 오래되면 `stale: true`.
7. 사람이 그 질문을 닫았으면(2.6) 없다.
8. 코디네이터의 요약 표 속 질문 행은 지금처럼 질문으로 보지 않는다.

### 2.4 카드

- 남는 질문이 있으면 세션 행은 `lane: "human"`, `detail: "세션의 확인 요청 · <질문>"`, `decisionRequestedAt`은 질문 글의 시각, `keptQuestion: { key, later, stale? }`.
- 카드의 질문 본문, 앞 설명, 선택지, 질문 블록은 질문 글에서 읽는다. 선택지 이름표는 그 앞의 `since` 글에서 찾는다.
- 카드 버전: 남는 질문 카드는 대화 발췌 대신 `kept:<key>`로 버전을 만든다. 세션이 더 말해도 같은 카드다. 질문이 마지막 글인 카드는 지금처럼 발췌로 만든다.
- 코디네이터 판단이 같은 발췌에 있으면 지금처럼 그 판단이 앞선다.
- 답장 전 재검증(`server/decisions.ts`)은 같은 판정(닫은 질문 포함)으로 카드를 다시 만든다.

### 2.5 원장 카드가 있으면 닫힘

- 스냅샷에서 원장을 읽은 뒤, 남는 질문 카드를 가진 세션을 원장 카드가 가리키면(`sessionId`, `sessionMatch.sessionId`, `matchedSessionId`) 그 카드를 내리고 세션 행을 남는 질문이 없을 때의 판정으로 돌린다.
- 질문이 마지막 글인 카드는 지금처럼 둔다.

### 2.6 이 질문 닫기

- RPC `board.close-kept-question`: 입력 `{ sessionId, key }`(`key`는 1~64자), 출력 `{ ok: true }`.
- 서버는 세션이 관리 범위에 있는지 확인하고 호스트 설정 `closedQuestions[sessionId] = { key, at }`에 쓴다. 세션마다 하나만 두고(새로 닫으면 덮어씀), 전체 200개를 넘으면 오래된 것부터 지운다. 세션에 아무것도 보내지 않는다.
- 옛 설정 파일에 필드가 없거나 형식이 틀리면 빈 기록으로 읽는다.

### 2.7 더 읽기

- 보드는 지금처럼 끝에서 48개 항목을 읽는다. 다음이 모두 맞으면 앞쪽을 96개씩 두 번까지 더 읽는다: 더 오래된 항목이 있음, 읽은 범위에 사람의 입력이 없음, 읽은 범위의 어시스턴트 글에 질문 글도 해결 줄도 없음, 어시스턴트 글이 31개보다 적음, 가장 오래된 항목이 24시간 안.
- 앞쪽 읽기의 시대가 다르거나 오류, 빈틈, 낡은 커서면 거기서 멈추고 읽은 것만 쓴다.
- 원격 세션도 같은 읽기를 그 호스트에서 한다.

### 2.8 화면

- 남는 질문 카드에 한 줄: "이 뒤로 세션이 n번 더 말함 · 아직 답 없음" / "The session spoke n more times since · No answer yet". 오래된 질문은 앞에 "오래된 질문 · " / "Old question · "를 붙이고 카드를 흐리게 그린다.
- 그 줄 옆에 **이 질문 닫기** / **Close this question**. 누르면 RPC를 부르고 보드를 새로 읽는다. 실패하면 두 언어로 알린다.
- 세션 열기는 카드 머리의 **작업 세션 열기**가 맡는다.

## 3. 경계와 실패

- 사람의 입력이 발췌 범위 밖에만 있으면(더 읽기 상한까지 읽어도 없으면) 읽은 범위 안의 질문으로 판정한다. 그 질문이 상한 안이면 카드가 남는다.
- 타임라인 시각이 없으면 시간 상한과 오래됨은 글 수로만 본다.
- 더 읽기가 실패하면 처음 48개로 판정한다. 대화 읽기 전체가 실패한 것으로 보지 않는다.

## 4. 요구사항과 시험

| ID | 요구 | 시험 |
|---|---|---|
| R1 | 다른 세션 보고 뒤 질문 없는 답글에도 카드가 남는다 | `test/kept-question.test.ts` |
| R2 | 사람 글(빈 글 포함) 뒤에는 남지 않는다 | 같은 파일 |
| R3 | 해결 줄 뒤에는 남지 않는다(닫음, 옮김, 영어) | 같은 파일 |
| R4 | 원장 카드가 그 세션을 가리키면 내린다 | 같은 파일 |
| R5 | 30번 넘게 더 말했거나 24시간이 지나면 내리고, 절반을 넘으면 오래됨 | 같은 파일 |
| R6 | 질문 없는 세션, 질문이 마지막 글인 세션은 지금과 같다 | 같은 파일, `test/conversation.test.ts` |
| R7 | 남는 카드의 버전은 세션이 더 말해도 같다 | 같은 파일 |
| R8 | 사람이 닫은 질문은 남지 않고, 새 질문은 다시 뜬다 | 같은 파일 |
| R9 | 앞쪽 더 읽기는 조건이 맞을 때만, 상한까지 | 같은 파일 |
| R10 | 카드 줄 문구(두 언어, 오래됨) | 같은 파일 |
| R11 | 닫기 기록은 세션마다 하나, 200개 상한, 옛 파일 호환 | 같은 파일 |

## 5. 버린 설계

- `since`를 `turns`에 섞기: 코디네이터에게 내는 발췌 모양이 바뀐다. 따로 둔다.
- 해결 줄을 마지막 글에서만 찾기: 세션이 해결을 밝힌 뒤 또 다른 보고에 답하면 질문이 되살아난다. 질문 뒤의 모든 글에서 찾는다.
