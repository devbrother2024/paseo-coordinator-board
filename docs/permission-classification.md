# 셸 권한 분류 명세

`classifyShellPermission`은 셸 요청의 명령 문자열과 작업 폴더를 받아 명령별 분류 및 최고 위험을 반환합니다. 보드는 이 결과로 카드의 제목과 명령 묶음을 표시합니다.

- 읽기 등급은 지원하는 명령과 정확히 일치하는 옵션에만 적용합니다. 값을 받는 옵션과 붙여 쓴 값만 허용하는 선택 값 옵션을 구분해 파일 인자가 누락되지 않도록 합니다. 알려진 쓰기·실행 옵션의 약어는 해당 위험으로, 나머지 옵션과 지원하지 않는 인용·셸 문법은 `unknown`으로 표시합니다.
- 민감 경로 목록과 작업 폴더 경계 판정은 `shared/permission-read-paths.ts`에 있습니다. 읽기 대상과 입력 리디렉션의 경로 문자열을 비교합니다. 상대 경로, `..`, Git의 `-C`에 따른 이동을 반영합니다. `cd`는 실패하거나 조건에 따라 건너뛸 수 있으므로 이후 읽기에 이전 폴더와 변경 가능한 폴더를 함께 고려합니다. 가능한 폴더가 너무 많아지면 이후 파일 읽기를 작업 폴더 밖 가능으로 표시합니다.
- 패키지 설치는 네트워크 접근과 설치 스크립트 실행을 함께 표시합니다. `curl`·`wget`의 알려진 로컬 파일 입출력은 네트워크 접근과 함께 표시합니다. `gh`가 인증 토큰을 표시하는 요청과 `echo`·`printf`의 셸 변수 확장 등은 민감한 읽기로 표시합니다. 자격 증명과 변수 값은 조회하지 않습니다.
- 최고 위험은 `read`, `outside-read`, `sensitive-read`, `write`, `network`, `execute`, `destructive`, `unknown` 순서로 고릅니다. 카드 제목에는 함께 확인된 다른 위험도 표시합니다.

## Git 실행 환경

명령에 명시된 `--ext-diff`와 `--textconv` 및 알려진 약어는 코드 실행으로 분류합니다. `--no-ext-diff`와 `--no-textconv`는 그 옵션을 끄는 읽기 옵션으로 인식합니다. Git은 외부 diff와 textconv 외에도 저장소·사용자 설정과 실행 환경에 따라 페이저나 fsmonitor 등을 실행할 수 있습니다. 예를 들어 `git status`와 `git log`는 요청 문자열만으로 그 실행 여부를 판별할 수 없습니다.

분류는 호스트에서 명령을 실행하거나 파일시스템을 조회하지 않습니다. 파일 읽기를 발견하면 `readPathsUnresolved`를 반환하고 카드에 **심볼릭 링크 대상 미확인**을 표시합니다. 후속 자동 승인 정책은 실행 호스트에서 작업 폴더와 각 읽기 대상을 `realpath`로 확인하고, 해석한 경로로 작업 폴더 경계와 민감 경로 판정을 다시 해야 합니다. 해석에 실패하거나 실제 읽기 대상을 알 수 없는 경우에는 사람에게 확인을 맡겨야 합니다. 별칭, 셸 함수, 실행 파일, Git 설정, 마운트, 디렉터리 탐색이 방문하는 파일과 실행 시점까지의 경로 보장도 호스트 정책에서 다룹니다.

## 읽기 전용 자동 승인이 쓰는 부분

`shellPermissionTargets`는 같은 분류에 더해 각 명령이 읽는 경로(쓴 글자 그대로)와 그 경로를 읽을 폴더 후보, `cd`가 옮겨 가는 폴더를 돌려줍니다. 분류기는 여전히 파일시스템을 보지 않습니다. 읽기 전용 자동 승인(`shared/permission-auto-approve.ts`, `server/permission-auto-approve.ts`)은 이 경로를 세션 호스트에서 구성 요소별로 풀어(링크를 따라간 뒤의 `..` 포함) 작업 폴더 경계와 민감한 이름을 다시 확인합니다. 파서는 헤어닥과 here-string을 받은 명령에 `inlineInput`을, 따옴표 밖에 일부 셸만 확장하는 문자(맨 앞의 `=`, `^`, 중간의 `~`)가 있는 낱말에 `shellSpecific`을 표시합니다. 자동 승인은 이 두 표시와 모든 리디렉션을 거절합니다. 카드의 분류는 이 표시를 쓰지 않습니다. 출력을 정확히 `/dev/null`로 버리는 리디렉션(`2>/dev/null`, `>/dev/null`, `&>/dev/null`)은 파일에 쓰지 않으므로 파서가 리디렉션 대상에서 빼고, 카드도 쓰기로 표시하지 않습니다. 자동 승인이 쓰는 민감한 이름 목록(`guardedWord`)은 카드의 "민감한 파일 읽기" 표시보다 넓고, 경로가 아닌 인자에도 적용합니다. 자동 승인의 조건 전체는 `intent/permission-auto-approve/spec.md`에 있습니다.

## 알려진 한계

- 네트워크 명령의 세부 표시는 확인된 옵션에 한정합니다. 일부 로컬 파일 입출력이나 자격 증명 접근은 요약에서 빠질 수 있습니다. 후속 읽기 전용 자동 승인 정책은 `network` 이상인 요청을 제외합니다.
- `git clone`은 `network`로 분류합니다. 복제 대상 폴더와 로컬 파일 생성은 별도 위험으로 표시하지 않습니다.
- `wget --use-askpass`는 `network`로 분류합니다. 인증 도우미 실행은 별도 위험으로 표시하지 않습니다.
